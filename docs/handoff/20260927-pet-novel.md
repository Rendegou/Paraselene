## 4. 重要决策与踩坑

- **角色设计**：按用户反馈，从太复杂/太人形的方案收束为有明确轮廓和表情的原创月相小兽；参考的是 Clawd on Desk 自带 Calico、Clawd、Cloudling 的差异化设计方法，没有复制其贴图，也没有直接复刻漫画角色。月/星/云同一骨架，姿态按状态切换；视觉仍以正式 120px 原生窗口验收为准。
- **数据边界**：旧想法候选与导入预览只读；用户确认才写入。小说试写独立存 `novel_drafts`，正稿仅从 `novel_versions` 的当前 head 读，采纳要显式操作且拒绝过期 base；回滚移动 head，历史分支不删除。这保证未确认内容不会因普通读取进入正稿上下文，但未来 AI 组装仍需专门验证。
- **窗口与架构**：120px 桌宠和小卡片不承担长文编辑，小说用独立 960×720 窗口；React 组件通过 `src/lib/ipc.ts` 调用，Tauri 仅薄转发，数据规则放在纯 Rust crate。Tauri 2 的 WebView 窗口创建在同步命令里曾有卡住风险，当前新命令采用 async 创建；原生行为尚未证明。
- **编译坑**：最初的小说 `query_map(...).collect()` 放在块尾触发 Rust E0597 临时借用寿命错误，改成局部 `rows` 后核心测试通过。受限环境中链接到正式仓库的 `node_modules/.vite-temp` 曾使 Vite 返回 EPERM，获准访问后以前的前端构建成功；小说 UI 的本次 `pnpm build` 申请因自动审批超时未运行，不能当成代码失败或成功。
- **桌面验收坑**：Windows `SHQueryUserNotificationState` 曾返回 `BUSY=2`，正式宠物按安静逻辑自动隐藏；不要为截图随意禁用正式安静规则。内置浏览器拒绝本地 `file://` 检查页，不能以该页是否打开推断造型通过。曾尝试更新 Impeccable 技能，包地址返回 404，未完成更新，不影响已记录的本地静态检查结果。
- **检索与隐私**：FTS 的旧 trigram 评测曾未连到正式 `Database::search()`，现已修正并在正式 API 跑 24 题；短 snippet 不足以充当完整出处。真实导出和 Key 不进入仓库；`data/`、`secrets/` 与授权导出原文件都不得作为提交或排障日志内容。
