# 长篇小说工作台：产品与交互规格

更新：2026-10-03。状态：PLANNED。适用对象是逐章持续写作、需要自己审核 Agent 修改的作者。第一版保持已有“夜空手帐”视觉世界，正文优先，复杂工作在独立小说窗口完成。

## 1. 三个主区域

左侧：作品名、可折叠卷/章目录、搜索、章节状态；切换“章节”和“设定集”。章节有稳定顺序、字数、编辑稿/确认稿状态、需重建标记。顺序使用显式 order，不按创建时间猜剧情顺序。

中央：当前章节正文、标题、保存状态、版本入口。能写字、选段、查找、撤销、定位出处。顶部仅保留“编辑稿/确认稿”和必要动作；编辑稿可自动保存，确认正稿是单独动作。较重的版本历史按需打开。

右侧：同一区域切换“Agent / 修改 / 引用”。Agent 对话显示本次任务范围和上下文；修改页审阅 diff；引用页看设定、伏笔和人物动机出处。修改待审核时显示数量，不能强行抢走正文焦点。

```text
┌──────────────┬─────────────────────────┬──────────────────┐
│ 作品 / 卷章   │ 当前章 · 编辑稿 · 已保存 │ Agent 修改 引用  │
│              │                         │                  │
│ 章目录        │       小说正文           │ 本次请求与证据    │
│ 搜索          │       选段与定位         │ 或 diff 采纳     │
│ 设定集        │                         │ 或出处/反向引用  │
└──────────────┴─────────────────────────┴──────────────────┘
```

宽窗口三栏可拖动调整；默认中央占最大空间。较窄窗口把两侧收成可键盘打开的抽屉，不把正文压成窄列。分隔条有键盘调节与名称；侧栏、正文、diff 支持焦点回到来源。具体像素由原生 spike 确定，不复制 Cursor 的代码 UI。

## 2. 用户流程：选段改写与替换

1. 选中正文，打开“改写/只改对白/保留动作/续写”；任务范围显示当前章与选段。
2. Agent 准备真实外发内容，展示设定、原文、摘要、引用和预计 token；用户确认后发送。
3. 流式输出只出现在候选区；用户仍可编辑/取消。取消或失败保留已接收候选，标记不完整，不能确认正稿。
4. 修改页提供行/段差异，必要时展开字级差异；原文与新文均可读。可“应用此块”“应用全部”“拒绝”“继续讨论”。只有位置安全且非重叠的块允许独立应用。
5. 应用先修改编辑稿，产生可撤销的本机操作，不直接改确认稿。用户“确认正稿”后才产生新确认版本并触发摘要/索引失效与重建。
6. 生成期间手写、切章或版本变化，候选标成“基于旧版本”。后端再次核对，提供重新生成或显式人工合并；不默认模糊匹配替换。

应用多个块时要以原始快照统一计算或正确重定位剩余块，不能先应用第一块后让后续偏移错位。重复点按、网络重试不得重复插入。拒绝候选可留历史，但不加入下一次生成的正史。

## 3. Agent 对话

每次显示活动作品/章节/模式，支持 @人物、@设定、@伏笔、@章节引用。引用引用的是ID和版本；同名条目要用户分辨，不能只靠字符串名称。

支持讨论、选段改写、续写、跑团、连续性检查。讨论默认无正文写权限；涉及写入一律产出可审阅候选。跑团现有“两阶段场景→玩家行动”保留。会话压缩后展示已压缩说明与可查来源；聊天记忆不自动成为作品事实。

有明确的请求中/取消/失败/重试状态。失败显示可行动原因：预算不够、材料过期、云调用关闭、权限未确认、返回不完整；不能仅显示“未知错误”。

## 4. 设定集（Story Bible）

支持人物、关系、世界规则、地点/物件、时间线、禁忌、文风、未决问题。首版用结构化表单加备注，保留现有自由文本导入/编辑能力。

人物包含：别名、身份、欲望/目标、恐惧、价值底线、行为禁忌、关系、阶段性变化。每项可关联确认稿证据；作者手工设定也可无正文出处，但明确标为“作者确认”。

条目状态：候选、已确认、否决、已替代；候选默认不参与正史。设定版本有作用范围，区分回溯改设定与从某章节起改变。同名人物不同实体不自动合并。

作者未来计划可以手动关联任务，但默认不会作为当前角色已经知道的事实。所谓硬约束表示发送前必须保留/核对的已确认条件，并不保证模型一定遵守；输出还需检查与作者审核。

## 5. 伏笔与人物动机

伏笔记录：描述、状态（计划/已埋/发展中/已回收/放弃）、埋设位置、相关人物/物件、预期或实际回收位置、证据与版本。未来回收计划和已发生回收分开；仅已确认位置作为事实。

动机链记录：角色此时想要什么→已知信息→触发事件→行动→结果，每个节点可引用原文。事实、角色信念、作者意图、AI解释分开显示。模型推断只能是候选，不宣称理解了“唯一真实动机”。

选段后显示“相关设定/前置证据/后续引用”。作者可查看未来章反向引用，但这不意味着生成当前历史章节时可以自动发送未来剧情。点击出处打开对应章节及版本并高亮；历史版本显示明确横幅，不悄悄跳到当前正文。

锚点无法定位或版本不再当前时显示“旧版出处/待重新定位”；不要高亮一个相似但错误的段落。作者可确认重绑定；新证据不覆盖历史记录。

## 6. 连续性检查

检查分两层：确定性规则（禁忌、引用存在、章节顺序、版本）和语义候选（动机跳跃、认知越界、伏笔未回收、世界规则冲突）。结果包含严重度、理由、确切证据、规则版本和是否人工确认；语义候选不得宣称100%准确。

用户可逐条忽略/覆盖并写原因，覆盖记录绑定候选/规则/作品版本。设定或正文变化后重新评估，不把一次忽略当作永久豁免。

## 7. 恢复、空态与可访问性

- 空作品允许手写第一章或新建设定；没有摘要时说明尚未构建，不假装读取了全文。
- 目录加载不冻结编辑；索引失败不阻止本机写作；需要失效材料的生成明确补建或降低范围。
- 保存状态区分“正在保存/已保存/保存失败/有待恢复稿”；失败时保留正文并允许重试/用户主动导出。
- 重启恢复最后收到保存确认的编辑稿、章节和必要操作状态；未收到确认的最后输入不能保证存活，UI需明确。
- 中文 IME 组合输入过程中不抢焦点、不触发选段替换；验证 emoji、组合字符、换行与撤销。
- 正文、目录、Agent、diff、出处都可键盘操作；插入/删除有文字标记，不能只靠红绿；缩放与 reduced-motion 可用。

## 8. 不在首版范围

一键完成整部小说、多人实时协作、版权/发表服务、自动云同步、多Agent编剧军团、外部图/向量服务、花哨关系图。能力完成后再讨论扩展；首版要先写得顺、改得安全、找得到出处。
