### 修复报告通道后的原生反例

先前通过 `document.title` 报告结果不会同步到 Tauri 原生窗口标题，改由本地 `probe-result.html?report=…` 导航回传。2026-09-28 在 Windows WebView2 运行了以下逐步实验；都只用固定公开目标、无用户代码或私人文件：

1. 普通模块 Worker、原产品 CSP：`fetch('https://example.com/', { mode: 'no-cors' })` 返回 `resolved:opaque`。这证明**原 Worker 方案可发外网请求，G13 不能通过**。`file:///C:/Windows/win.ini` 读取失败，Worker 未见 Tauri 全局桥接。Pyodide 314.0.7 要求模块 Worker；改为模块并补齐本地 `pyodide-lock.json` 后可启动。
2. Blob Worker 继承创建页面 CSP。只在探针构建中以 `TAURI_CONFIG` 开启 `worker-src blob:`；页面 CSP 将外网、文件与 IPC 地址排除在 `connect-src` 外。为克服 Blob Worker 读取 `tauri.localhost` 静态资源时的 CORS 问题，探针示例注册仅允许五个固定 Pyodide 资源的 `probe-assets` 协议。该协议不开放任意路径读取。产品配置文件未改。
3. 页面调用 `probe_ping` 仍得到 `pong`，尽管页面也记录了对 `http://ipc.localhost/probe_ping` 的 CSP 违规。**页面 CSP 不能作为 Tauri 命令的隔离证明**；真正执行不可信 Python 的 Worker 才是隔离边界，产品主页面不能运行用户代码，也不能把 Worker 消息直接转发为 IPC。
4. `& .\scripts\run-webview2-probe.ps1 -PyodidePackagePath 'D:\paraselene\spikes\pyodide\node_modules\pyodide'`：最终退出码 **0**，关键输出 `PROBE_PAGE_LOAD:Finished:/probe-result.html`、`PROBE_ASSERT:PASS`。断言检查 Pyodide 确已加载；Worker 无 `__TAURI_INTERNALS__`、`ipc` 或 `chrome.webview`；Python `os.path.exists('C:/Windows/win.ini')` 为 false；Python `js` 中无 Tauri 桥接；JS 外网、文件、IPC `fetch` 和 Python `js.fetch(..., mode='no-cors')` 均拒绝；CSP 违规记录覆盖外网、文件与 IPC。

本结果只证明**探针环境中的固定反例**。G13 仍为 PARTIAL：产品还没有接入按需加载/销毁的隔离 Worker、结果消息白名单与真实练习运行入口，也未在正式使用路径复跑这些反例。尤其不能把 `fetch` 失败单独解释为安全；此次以 CSP 违规事件和拒绝结果共同作证。Pyodide 模块 Worker 的要求见 [Pyodide 官方文档](https://pyodide.org/en/latest/usage/webworker.html)，Tauri CSP 与自定义协议的边界见 [Tauri CSP 文档](https://v2.tauri.app/security/csp/)及 [Tauri 自定义协议 API](https://docs.rs/tauri/latest/tauri/struct.Builder.html#method.register_uri_scheme_protocol)。
