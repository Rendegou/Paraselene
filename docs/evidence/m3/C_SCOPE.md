## 必须解决的问题

1. 把原始正文、全局UTF-16选区/composition与可见布局分开。
   先评估保留完整原生TextInputClient状态，只虚拟化渲染，避免过早裁剪IME上下文。
   如果平台传输成本超预算，再单独比较有明确投影合同的窗口化输入。
2. 保留CRLF/LF、Unicode标量和grapheme；分片不成为作者换行或正文字符。
3. 显示可见段落/超长行的有限布局，记录实际每帧layout字符数量。
   页面边界要验证连续排版和双向文字，不能只用不相连的TextField冒充跨段编辑。
4. 全局选择、复制/剪切/粘贴、全文删除/撤销，组合输入跨LF边界及槽位显隐保留焦点。
5. 先测固定合成矩阵，再真实Windows输入；框架注入只算框架测试。

## 验证顺序

- 文档事务/坐标/组合区模型及边界测试。
- 有界虚拟排版与全局输入面，和完整小样本文本布局作几何对照。
- 10k/200k/超长单行/Unicode/空章；另加入不重复的长章防止缓存只对重复fixture有效。
- 记录profile装载、编辑到框架帧、持续滚动、内存和原生回调。
- 真实Windows中文输入、全选/删除/撤销、跨段选择与讨论槽位。
- 独立审查、证据及ADR；失败仍停在spike，不放宽预算或伪称M3通过。

输入P95≤50ms、20万字装载≤1s、普通滚动不持续>33ms保持不变。
