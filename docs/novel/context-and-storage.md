# 长篇上下文、数据与恢复契约

更新：2026-10-03。状态：PLANNED，供 T05A–T05H 实现。保留当前 SQLite 与不可变确认版本底座，不使用“更大上下文窗口”替代结构设计。

## 1. 三个独立问题

- 编辑性能：全书按章存、目录只读元数据、正文按需加载、视口渲染与受限缓存。
- 叙事连续性：确认正文/作者设定作为权威，摘要、事实检索和人物状态帮助选择相关材料。
- 可靠性：编辑稿保存、版本条件、幂等 patch、取消、任务阶段和派生索引重建可恢复。

这三条分别测试；模型能读长上下文不等于编辑器不崩溃，编辑器能显示长文不等于人物不会失忆。

## 2. 权威、候选与派生物

权威数据：不可变确认稿版本、作者确认的设定/事实、明确的章节顺序和作者确认的引用关系。

编辑稿：本机 working copy，包含已保存 revision；不会自动成为确认稿。AI候选与未完成流单独保存，默认排除出正史上下文。作者可在单次讨论中显式引用候选，manifest 必须标明候选且不能将其提取为确认事实。

派生物：章节摘要、卷/阶段摘要、实体索引、事实抽取候选、检索 chunk、向量（后续可选）。必须保存来源版本集合/哈希、算法或提示版本、状态、构建时间。它们不替代原文，不能自证引用。

修改/回滚/删章/重排时派生物失效。重排影响所有依赖章节区间、时序事实和累积摘要；只改标题无需重写正文摘要，但名称索引和预览票据需按依赖失效。没有可信派生物时本机编辑可继续，生成明确等待补建或选择更小证据范围。

## 3. 建议存储实体（表名/字段为设计，尚未建表）

- work/chapter：作品、卷章层级、稳定ID、order_key、状态；既有 works/novel_documents 对应保留并渐进扩展。
- novel_versions：沿用不可变正文与parent/head；保存作者采纳关系，回滚移动head，不改写历史。
- working_copies：work_id/document_id、base_head_version、revision、正文、已确认保存时间、content_hash；更新按 expected_revision 比较。
- generation_jobs：operation_id、状态、输入快照ID、context_manifest_id、候选ID、取消/错误码、幂等键。状态 prepared→running→candidate_ready/failed/cancelled，崩溃后 running→interrupted。
- input_snapshots/patches：不可变任务输入、base_head_version、base_working_revision、before_hash、锚点、replacement、候选状态；多块共享一个输入快照。
- lore_entries/lore_versions：人物/世界/禁忌等，确认状态、作者/抽取来源、别名、有效范围、硬约束标记；现有设定文档可一对一迁移，历史原文保留。
- source_anchors/reference_edges：作品/章/不可变版本、坐标单位、起止、引用片段hash；边有类型、事实/信念/作者意图/推断、确认状态。
- foreshadow_threads/motivation_chains：节点、状态、关联人物、叙事位置、来源边；未来计划与确认回收分离。
- chapter_summaries/derived_dependencies/rebuild_jobs：来源版本、范围、算法版本、dirty/ready/failed、进度、重试与claim信息。
- context_manifests/context_items：任务范围、模型预算、实际引用ID/版本/锚点、预计token、选择/省略原因、校验指纹。

所有记录按作品作用域；不能只用document_id绕过work校验。删除策略保留已有软删除语义，新增永久清除需专门范围与用户授权。不要把旧学习数据顺手删除。

## 4. 出处和选段坐标

前后端新契约统一 IPC 的 UTF-16 code unit（与编辑器坐标匹配），字段显式带 `coordinate_unit`。Rust 用唯一测试过的转换函数处理 UTF-16↔UTF-8/char，禁止把 offset 当 `.chars()` 序号直接切。既有 code point 接口由适配层转换，不能静默换字段意义。

锚点至少包含 work_id、chapter_id、source_version_id、start/end、quote_hash；在不可变来源快照核对边界与片段。UI可附简短引文用于用户识别，但日志不输出正文。下一阶段可增加稳定段落ID；先做到历史版本可精确跳转。

patch还须绑定base_head_version与base_working_revision；应用前核对所有条件和原文hash。重复语句、emoji、组合字符、CRLF→LF、选段跨段落必须测试。行结束符在新输入边界统一，老快照按既有原文解释，不能先规范化再沿用旧offset。

过期锚点不得自动定位到相似句。可展示历史位置；显式重定位需核对候选并保存新边，保留旧出处。单块采纳后其它块以同一原始快照统一计算新偏移或标过期，不能继续用旧offset盲写。

## 5. 时间、认知与引用范围

任务范围包括目标章序/场景位置、叙事时间、POV人物、模式（历史改写/当前续写/作者规划）。章序与故事时间不同，双线/倒叙作品不能简单按created_at筛选。

默认改写第k章：只读取在该场景已可用的正文事实、阶段人物状态及当时有效设定。全书摘要若含后续剧情不能用于此请求，应选截至该范围的摘要。作者未来大纲是“计划”，不当作已发生事实；POV人物知道的内容还需更窄筛选。

作者可在UI浏览后续反向引用/回收计划，并显式开启作者规划范围；manifest 将未来内容标为作者层资料。模型回复与候选事实仍不能把未来事件说成角色已知。无法判定范围的条目标 unknown，需作者确认，不自行猜测。

## 6. 上下文流水线

1. 捕获作品、章节、编辑revision、目标范围及明确用户操作，创建不可变输入快照。
2. 加载当前有效硬约束、用户显式引用和当前选段/邻接段；验证来源和作用域。
3. 查询适用的近期章节/阶段摘要、人物状态和未解决伏笔；只用ready且依赖仍匹配的派生物。
4. 在本作品、确认版本、允许时序内检索相关原文。首版本机FTS5/trigram/别名＋结构化边；语义向量后续加，不默认外发embedding。
5. 去重、排序和预算装配；引用保留最小完整证据单元，不在句中随便砍掉条件/否定词。
6. 返回实际 manifest 和实际拟发送内容供外发预览；生成一次性票据。
7. 用户确认时重核依赖/编辑revision/模型配置；预览后变化则票据过期，重新准备，不发送未预览的新材料。
8. 请求输出仅产生候选。模型引用ID必须匹配manifest并核对原文；不存在的引用标无法验证，不生成链接或入库正史。

## 7. Token 预算

`input_budget = model_context_window - output_reserve - protocol/system_overhead - safety_reserve`。模型/上下文/输出上限来自显式配置与经核对的供应商元数据；不把字符数等同token，不硬编码“某模型永远支持某数字”。估算器有名称、版本与误差裕量，UI显示“预计”，若供应商返回用量则另记录实际计数。

优先顺序：必要指令/约束与目标选段→显式引用→当前场景/近期状态→相关原文→更远摘要→可省略聊天。任务不同可采用不同配额，但必需内容不可静默丢弃。装不下时本地返回“必需材料超预算”，展示原因/可缩小范围，不先发请求碰运气。

长会话摘要保存对话范围与原消息ID，区分决定、建议、未决项；不能仅依据AI聊天总结修改Story Bible。压缩原消息仍可回查，摘要过期/失败不覆盖上次有效版本。

检索记录命中/省略原因、计数和耗时；详细正文只在受控本机预览/数据存储显示。外发日志和分享包不含正文。故事文本是资料，不是解除权限/云开关的执行指令。

## 8. 编辑、保存与崩溃恢复

目录API只返回ID/顺序/标题/状态/字数/head，不带head_body。正文按当前章请求，历史版本按需分页；前端缓存上限按章数与字节共同限制。不在每次击键统计全书字数或重算全部diff。

自动保存建议500–1000ms合并本机编辑操作，具体取值由T05B基准确认。IME组合期间不扰动输入；必须显示最后持久化revision。切章/关闭窗口尽力flush，失败有明确保留/导出入口；异常退出只能保证已收到保存确认的版本。

后台diff限定当前候选/章节，大输入有取消和计算预算；先段/行匹配，再只在变化块做字级diff。不要构造全书两个字符串并跑二次方算法。单章超规格不静默截断，要允许用户显式拆章或只选段比较。

SQLite事务保存确认版本、head更新及dirty标记/outbox；摘要/索引生成在事务外。任务产物写入时再次核对source版本；期间变更则丢弃旧产物并重新排队。重启恢复队列，重试幂等，失败可见，不能把failed当ready。

生成流定期将候选checkpoint落本机，次数/字节有上限；断网/崩溃后标不完整，让作者决定重新生成。没有供应商续传协议时不能宣称“从token无缝续跑”；新请求需重新预览。每个作品/章节的写入串行化，跨窗口陈旧写拒绝。

## 9. 迁移与兼容

检查当前实际migration最高版本再添加下一版本，不提前假定新版本号。用合成V5/V6库验证升级、重启和历史版本完整性；不访问用户数据库验证破坏性迁移。顺序无法从旧模型可靠推导时展示待确认顺序，不按时间猜用户章节。

旧设定先映射为作者确认的自由文本，结构化字段逐步补；没有自动抽取即不伪造人物关系/动机。现有IPC/窗口入口保留适配层，逐阶段切换。

## 10. 不变量与限制

- 工作副本自动保存 ≠ 正稿；摘要 ≠ 原文；模型推断 ≠ 作者确认。
- 引用必须可复查来源版本；预算和省略可解释；硬约束超限不能隐身。
- 过期patch/外发预览/摘要不会覆盖当前状态。
- 确认正文保存失败时head不前移；派生重建失败时编辑不丢失。
- 首版没有“永不崩溃/永不OOC/全书都能一次读完”的保证；按 [实施计划](implementation-plan.md) 提交可复跑的可靠性与质量证据。
