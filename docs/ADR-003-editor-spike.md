# ADR 003：正文编辑器 spike 未通过，暂不接入正式工作台

日期：2026-10-15。状态：**选型暂缓；M3 未完成。**

C验证期间发现A/B原pubspec的包外字体没有进入Windows bundle，下列历史性能数字
保留但不再称为固定字体对照。现已修正并重测：A/B的20万字编辑P95约85/214ms，
仍超50ms预算；B装载约865ms，原装载失败结论已被取代。
见 `evidence/m3/FONT_CORRECTION.md`。B复制/撤销缺陷独立成立。

## 决策依据

遵守迁移计划第8节与M3出口：先比较候选，失败停在 spike 并评估路线。
M2 工作台仍只读；本次没有改动正式应用、Rust schema 或作者数据。

已实现隔离 A（EditableText + LF 等长 WidgetSpan）与 B（Quill 11.5.0 +
纯文本映射/block embed）。同机 profile、760 logical px 正文、20px/1.85、
居中焦点下，20万字编辑 UI-frame 代理 P95 分别约 **467ms / 270ms**；
单逻辑行分别约 **523ms / 518ms**。预算仍为输入 P95 ≤50ms，不能放宽。
本探针未测原生按键到显示器呈现，但仅编辑到框架帧已明显超预算，不能准入。
B 的20万字单次装载约1066ms，也未落在≤1s预算内；装载尚无重复分布。

原 CodeMirror 源引擎隔离浏览器基线的相同 BMP fixture 输入代理 P95约8ms，
但宿主、字体文件格式、输入触发、帧边界和高度不同，禁止直接宣称倍数比较，
或把它当作完整原客户端/WebView2验收。详见证据报告。

## 能力与缺口

- A：真正为段下占位腾出空间，保留原始CRLF及UTF-16长度；组合区、
  controller/focus/scroll身份的重建测试及精确复制平台通道测试通过。
  真实Windows拼音候选窗和“你好”提交已观察到并保存composition回调。
  当前仅支持首个LF槽位；EOF/无LF、百线程、完整锚点和生产事务仍未实现。
- B：block embed确实占空间，基本纯文本映射有测试；当前适配器会污染复制、
  撤销，删除embed会留下额外换行。测试明确复现这些缺陷。
  这些是当前适配器的问题，不证明整个Quill库无法支持需求。
- 两候选均没有通过完整原生IME/DPI/跨屏/快捷键/滚动/资料焦点矩阵。
  widget注入不是IME；单次jumpTo不是持续滚动；重建不是稳定切线程。

## 后续路线与投入边界

建议把候选 C 的**隔离可行性验证**作为下一个决策，先验证按段虚拟化、超长单行
分片和统一选择/IME输入面，而不是直接全量重写。粗估3–5个有效工程人日，
包含选区/组合输入原型、20万字/单行性能、段下槽位及同机复测；不含正式编辑器、
保存和持久讨论。估算置信度低，单行分片与跨段IME是主要不确定性。

如果验证通过，C 的生产化另估12–20人日，覆盖事务/history/锚点、剪贴板、
可访问性、焦点与多语言全矩阵；这是新增估算，不是交付承诺，也不能与已花时间
简单相加冒充原M3预算不变。验证失败应重新评估宿主/复用CodeMirror等路线，
另立ADR，不自动改架构。

**2026-10-15 用户已明确回复“是”，接受C隔离验证范围与3–5有效人日粗估。**
C现已进入隔离验证，仍须过同一门禁；该授权不等于批准生产化12–20人日或数据接管。

## 回退

正式运行入口保持M2提交 `faec2bc` 的只读工作台。spike为独立目录，可停止运行；
没有需要回滚的作者数据库写入，不进入M4或作者数据接管。
