## 第三轮：单次排版优化与裁决（2026-10-15 晚）

用户裁决规则："优化代价大就通过，不大就不通过"。为回答该问题，先落地了最便宜
的一档优化：`_advance` 的页高直接取自探针自身的行测数据，删掉为求页高而做的
第二次整页 TextPainter 排版（同文本前缀行几何一致；超长可视行的 StateError
守卫与探针生命周期顺序保持不变）。

证据：51 项测试通过（`m3/c-round3-test.txt`）、analyze 无问题
（`m3/c-round3-analyze.txt`）、`flutter build windows --profile --target=lib/c_main.dart`
成功（`m3/c-round3-build.txt`）、字体包校验通过（`m3/c-round3-font-bundle.json`）。
同机 profile exit 0，结果覆盖写入 `m3/c-profile.json`；第二轮结果备份为
`m3/c-profile-round2-incremental.json`。注意：一次未带 --target 的误构建曾把 exe
建成 A/B 入口并重写了 `m3/flutter-profile.json`（该文件 19:11 的内容是本次误跑
产物，A/B 固定字体对照仍以 `m3/ab-font-validated-profile.json` 为准）。

排版单位计数因取消双重排版降至 50%/67%，但帧时间收益有限：stress 全幅滚动仍在
两个非重复样本上失败（连续 118/120 帧 >33ms），中段冷跳 2319.4ms。结论：这两项
不是"顺手能修"的缺陷——它们是懒测量架构的固有代价（不测量就不能精确画）。
继续消除只剩两条路：(a) 高速滚动/冷跳期间允许按估计位置绘制再校正，等于放宽
"绝不画估计正文"的验收口径，属产品契约决策；(b) 后台 isolate 排版，Flutter 对
跨 isolate 的 ui.Paragraph 支持不确定，属多日高风险工作。

按用户规则判定：剩余优化需要动验收契约或架构，代价大 → **C 隔离可行性验证通过**。
接受的限制：stress 全幅滚动掉帧（0.7 秒甩完 20 万字的合成压力负载，非普通滚动）、
无换行长文档首次中段冷跳约 2.3s（有段落文本为 80ms 内）。M3 仍不宣称完成：
通过的是"C 可行"这一决策点，生产化（ADR-003 另估 12–20 人日）与 M4 均未授权。
