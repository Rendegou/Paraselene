## 范围与事实

- REAL：前端的预览、发送、模型列表通过 `AgentRuntime` 调用现有原生适配器，Tauri IPC 命令和后端授权逻辑保持原状。
- REAL：契约与驱动不依赖 Tauri；预览对象绑定签发实例、复制并冻结，发送前消费。显式选择尚未注册的 dsh 会报错。
- SIMULATED：8 项契约测试使用合成文本和注入的传输，无真实模型、Key、WebView 或私人资料。
- PLANNED：产品 dsh 适配器、原生受控模型出口、端到端取消与 Windows 验收。M02 的真实进程实验单独记录，不能替代这些验收。
- 未修改 Rust、数据库格式、用户数据、窗口权限或现有云调用授权。G01–G20 的历史状态不因本次测试自动更新。

## 工具链与实际命令

执行环境：Linux x64 云环境，PowerShell `7.5.4`、Node.js `22.21.1`、pnpm `11.25.0`。Windows 本机验证未执行。

云环境的预装 `pnpm` 包装器固定调用 Node 24，故使用 Node 22 直接执行其 CLI。本轮实际使用以下前缀，后接表中的参数；每条命令读取 `$LASTEXITCODE` 作为退出码：

```powershell
$env:PATH = "/workspace/tools/node22/bin:" + $env:PATH
Set-Location /workspace/Paraselene
& /workspace/tools/node22/bin/node /opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/pnpm/bin/pnpm.mjs install --frozen-lockfile
& /workspace/tools/node22/bin/node /opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/pnpm/bin/pnpm.mjs typecheck
& /workspace/tools/node22/bin/node /opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/pnpm/bin/pnpm.mjs typecheck:runtime
& /workspace/tools/node22/bin/node /opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/pnpm/bin/pnpm.mjs test:runtime
& /workspace/tools/node22/bin/node /opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/pnpm/bin/pnpm.mjs build
```

普通 Node 22 / pnpm 安装可直接使用表中等价命令。

| 实际 CLI 参数 | 普通安装的等价命令 | 退出码 | 关键输出 |
|---|---|---:|---|
| `install --frozen-lockfile` | `pnpm install --frozen-lockfile` | 0 | `Already up to date`，锁文件可复用 |
| `typecheck` | `pnpm typecheck` | 0 | `tsc --noEmit` |
| `typecheck:runtime` | `pnpm typecheck:runtime` | 0 | `tsc -p tsconfig.runtime-tests.json` |

| `build` | `pnpm build` | 0 | Vite `8.3.1`，47 modules transformed，生产资源生成 |

测试脚本使用 `--experimental-test-isolation=none`，使本环境显示每项子测试。默认隔离模式在本环境仅显示文件级结果；单项测试不需要跨文件进程隔离。

初次依赖安装因 esbuild 安装脚本未获包管理器配置允许而退出 1；新增 `pnpm-workspace.yaml`，明确允许测试工具依赖的 esbuild 构建，随后安装和冻结锁文件安装均退出 0。没有放开任意依赖脚本。

## 断言覆盖

1. 构造与预览不发送请求；原生票据和流式事件保持原值。
2. 驱动修改原对象后，已显示预览仍不变。
3. 跨实例、跨引擎、复制对象和已消费预览被拒绝，不进入传输。
4. 并发重复发送只进入一次传输。
5. 传输失败保留错误，票据不会自动重试。
6. 模型错误保持结构化事件，不伪造完成事件。
7. 显式选择未接入 dsh 不回退到旧实现。
8. 取消能力声明不能宣称不存在的实现。

## 结论与限制

M01 的跨平台接口、现有界面接线、类型检查和 Web 构建通过。原生 IPC 行为由未变更的后端继续负责，本轮没有运行 Windows UI、凭据库、Rust 工作区或性能验收。此结果不代表生产后端已迁往 dsh。
