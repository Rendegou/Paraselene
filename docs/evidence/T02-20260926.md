## 关键设计决定

1. **隔离下沉到 DDL**：`CHECK(space!='novel' OR work_id IS NOT NULL)` + `CHECK(space='novel' OR work_id IS NULL)`——"小说角色的话永远不能当成用户个人经历"由数据库强制，不靠 API 自觉。
2. **无全空间查询入口**：list 必须按 space 过滤，全局视图若需要应是显式产品决策重新评审（spaces.rs 模块文档写明）。
3. **memory_sources 不加 FK**：出处链要在会话被清理/重导入后仍可展示，级联删除会抹掉用户确认过的证据。
4. **链接单向可见**：from 侧见出链（actor=user），to 侧无反向；跨空间链接只允许 `link_memories` 显式写入（Goal §4.2 红线入注释）。
5. **瘦身组合（测量驱动）**：实测 tool 角色占文本量 78%（322MB/412MB）→ tool 不进 trigram FTS（精确词检索仍由 unicode61 全量覆盖）；单条消息入 FTS 文本截 4096 字符（原文完整保留 messages 表）；trigram 表从 external content 改独立表（前缀索引与 rebuild 语义不兼容）。

## 插曲与修正（诚实记录）

- 变体对比最初把"整个 scratch 库（含 messages 副本）"误当索引体积，口头估算偏高；已用 dbstat 逐对象实测修正，相关注释全部改为准确数字。
