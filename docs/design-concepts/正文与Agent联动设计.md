# 正文与 Agent：让讨论成为稿件的一部分

日期：2026-10-12。状态：草图已获用户认可，UI-01B 已按此实现活动 React 前端。最新行为与限制见 [实现验收](../evidence/NOVEL-COWRITE-20261012.md)。以下保留草图阶段的诊断、建议与历史验证；其中“未修改生产组件”等描述只针对当时草图阶段。

## 现场诊断

读了用户给出的《去AI味-诊断与施工手册》和《为什么有AI味道》，核对活动组件并查看当前内置浏览器。

- AgentConversation 固定显示同一段示例审阅；切章节没有形成对应的讨论范围。
- AgentComposer 的选段只显示字数，没有可核对的原文；stageInstruction 只记录指令，选定资料没有附在消息里。
- 人物/地图详情替换正文主区域，Agent 保留此前章节；查看资料与正在写的任务分离。
- 修改集中在独立面板，正文没有同位置的候选预览、讨论标记或相互定位。
- 实际浏览器宽 414px，正文容器约 366px；Agent 为 absolute 覆盖面板，宽约 320px。讨论时稿件几乎不可见。这是当期可复现的布局问题。

这轮先改变协作关系，再补字号、token、选中/禁用/焦点等工艺。统一配色不能单独解决正文与 Agent 的脱节。

## 推荐布局

宽窗口：左侧一个作品目录，中央正文，右侧浅色共写页边区。保留暖白正文与深灰顶部工具栏；共写区属于同一张稿件工作面，颜色和分隔方式比现有深色独立聊天区更轻。

窄窗口：正文在上，共写区从底部展开；同时保留正在讨论的原文。全屏讨论作为作者主动选择的模式，不默认遮掉正文。空间不足时收起目录、次要统计，不压缩核心中文字号。

角色/规则/地点从正文名字或消息来源打开时，在旁边查看资料，保持稿件滚动位置与编辑焦点可恢复。作者点击“展开资料”时才进入完整人设/世界观/地图工作区。

## 交互闭环

1. **发起**：选文出现“讨论选段 / 改写 / 提取设定”。不选文时作用范围是本章。选中不自动发送，也不清掉已输入的指令。
2. **确认目标**：共写区显示章节名、选段原文和引用资料，均可点击定位。作者锁定后，点击正文其它位置不会悄悄换掉本次目标。
3. **讨论**：消息归属本章；需要时绑定明确选段。正文只在有讨论/候选的地方出现小标记，双向定位，不给每一段预建空线程。
4. **查依据**：人物、场景、世界规则是可阅读的资料引用。先核对，再点“带入这次讨论”。当前 POV 已知信息与作者未来计划分开选择。
5. **审阅**：候选在原段落就地呈现修改前后；共写区解释意图、依据与采纳/拒绝。批量修改再提供集中审阅；首版从单选段闭环开始。
6. **采纳与继续**：应用到编辑稿，明确可撤销。确认正稿仍是独立动作。正文版本变化后候选过期，不能依靠屏幕位置重新猜测原文。

右侧默认名称可以是“本章共写”，查资料时为“查看设定”，审阅时为“审阅本段修改”。重要的是这些状态真实跟随工作内容；名称替换本身不算联动完成。

切章时自动跟随新章的讨论；未发出的指令按章保留。跨章任务必须明确显示目标范围，可手工固定。讨论锚点在实现中用文档 ID、版本/revision、范围和引文核对，不能把“第5段”或像素坐标当稳定 ID。

## 如何使用两份审计文档

采纳：统一语义 token；关键中文字号提升；选中态悬停仍可辨认；禁用与待处理状态不同；引用减少药丸，改为原文摘录和文字来源；去掉工具区营销式欢迎句；选中/定位/采纳使用短、明确的反馈。

需要重新验证：文档里的颜色/控件统计不是本轮测量。宋体本身是衬线字体；实际 fallback 与屏幕可读性应在 Windows 验证。token 的语义角色也不会自动保证所有组合的对比度。动效数量、阴影层数、噪点与渐变不是产品质量的必要条件。手册模板的“两端对齐”与其正文的“左对齐”互相矛盾，这里采用左对齐，并保留作者段落结构。

不把批量加动效、纸纹、印章作为本轮目标。先让作者看懂正在讨论哪段、依据在哪、改动落在哪，再根据实际使用打磨。

## 更合适的参考

- [Scrivener Inspector](https://www.literatureandlatte.com/blog/get-to-know-the-scrivener-inspector)：说明批注与单份文档关联，点击批注高亮正文。借鉴双向定位及稿件旁的资料检查；Scrivener 不是开源移植底座。
- [novelWriter 标签与引用](https://novelwriter.io/docs/usage/tags_and_references.html)：人物、地点、世界元素与小说章节/场景交叉引用。借鉴资料组织与故事语义，不将其标记语法强塞进作者正文。

coding Agent 的任务状态、版本核对和修改审核继续作为机制参考；主界面的组织依据改为章节、场景、人物与文本批注。

## 独立草图及下一步

[交互草图](document-agent-linkage.html) 只展示第三章的一个虚构段落，切换“讨论选段 / 查看设定 / 审阅修改”，可演示资料带入、就地候选、采纳/撤销。章节目录是布局示意；无模型、数据库或正式编辑器接线。

草图不改变 1422 根入口，复制到构建目录作为独立 `document-agent-linkage.html`，之后重新 build 会清掉该副本；文档目录源文件保留。与现有产品预览使用不同页面，不读写其 localStorage。

建议下一次施工只做这一条路径：选段 → 固定原文 → 讨论带出处 → 同位置候选 → 采纳/撤销。同步解决窄窗口遮挡与资料旁看。先验证作者不会丢失上下文，再接真实模型，不新增一套长期路线图。
