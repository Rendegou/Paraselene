## 二、核心结论

**这个项目的 AI 味，和大多数人以为的来源完全不同。**

它**没有**紫蓝渐变、没有 Inter、没有白底圆角卡片、没有三栏特性网格、没有 emoji 图标。它的冷灰底 + 暖白纸面 + 淡青绿，其实是有判断的配色。

它仍然像 AI 做的，是因为四个更隐蔽的原因：

1. **有 token 声明，但基本没被用。** 声明了 11 个变量，全文引用 **27 次**；而硬编码十六进制有 **190 处**。`StudioAgent.css`（整条右侧 Agent 栏）**一个 token 都没用**。
2. **配色是靠手调积累的，不是靠系统。** **194 个不同颜色值**，其中 **172 个（88.7%）以绿色通道为最大值**；读起来像"强调色"的有 **41 个，横跨色相 91°→153°**。声明出来的 `--studio-accent: #acd4c2` 在色相 153°（最偏青那一端），而实际在做强调工作的是色相 84–112° 的橄榄带（46 个值）。**声明的强调色不是界面在用的强调色。**
3. **全站没有动效。** 299 条规则里 **1 处** `transition`，而且那处在一个 `div` 上（地图画布）。**66 个交互元素，0 个有过渡。** 悬停是瞬间布尔切换，面板开合靠 `display` 切换（**`display` 根本不能过渡**）。同时 `prefers-reduced-motion` 块写得非常规范——**它守着一栋空房子**："安全网是生成的，被保护的东西不是"。
4. **没有深度。** 全站 **3 处 `box-shadow`，全是纯黑加透明度**（`#0004`/`#0002`）。`background-image`、渐变、`backdrop-filter`、噪点，**出现 0 次**。35 个表面填充对 3 个阴影。

**一句话**：它的问题不是"用了 AI 的默认审美"，而是**从来没有被排版过**。这对你是好消息——修正几乎全在样式层，不需要动布局和逻辑。

## 三、五个"只有读代码才能发现"的具体缺陷

这几条比配色问题严重得多，因为它们**直接影响可用性**：

### 1. 悬停会破坏选中态（层叠权重倒挂）

```css
/* StudioApp.css:19 —— 权重 (0,3,1) */
.studio-app button:hover:not(:disabled) { background: var(--studio-raised); }
/* StudioApp.css:63 —— 权重 (0,2,1)，输给上面 */
.studio-chapter-list > button.is-selected { background: #3c4940; }
```
**鼠标悬停在"当前章节"上时，它从橄榄绿 `#3c4940` (h138) 变成冷蓝灰 `#303438` (h210) —— 色相跳 72°。** 同一个 bug 还影响：导航轨当前页（跳 63°）、Agent 已开启的上下文芯片（跳 115°）、引用芯片（跳 106°）。

即"当前所在页面，鼠标一划过就不像当前页面了"。

### 2. 四个按钮在 DOM 里是 disabled，但样式上完全看不出来

`采纳到编辑稿`（`AgentPane.tsx:57`）、地图缩小（`WorldMap.tsx:93`）、地图放大（`WorldMap.tsx:104`）**都没有 `:disabled` 规则**。

其中 **`WorldMap.tsx:9` 的默认 `zoom` 就是 1，而缩小按钮是 `disabled={zoom <= 1}`** —— 也就是说**用户打开地图看到的第一帧，就有个看起来完全正常、点下去毫无反应的按钮**。

更糟的是 `.studio-source-list > button:disabled { opacity: 1 }`（`StudioContent.css:41`）—— 这是**主动把 disabled 样式抹掉**。

### 3. 报错提示是"粉色底 + 绿色上边框"

```css
/* StudioApp.css:86 设了绿色上边框 */
.studio-notice { background: #e7eddf; border-top: 1px solid #c6d0be; }
/* StudioApp.css:88 只覆盖了 color 和 background，边框留下来了 */
.studio-notice.studio-error { color: #873c32; background: #f5e5dc; }
```
结果：**暖粉色（h≈20）的报错条上，顶着一条橄榄绿（h93）的发丝线。**

### 4. 没装思源宋体，正文很可能根本没走衬线

```css
/* StudioContent.css:8 */
font-family: "Noto Serif CJK SC", "Source Han Serif SC", "SimSun", Georgia, serif;
font-size: 17px; line-height: 2.05;
```
前两个 Windows 默认都不装。**你看到的正文大概是 SimSun（宋体，屏显发虚）或直接回退无衬线。** 也就是说"小说正文该有的书卷气"这件事，目前是失控的。

### 5. 窗口变窄时，字号反向缩小

```css
/* StudioApp.css:123-124，@media (max-width: 650px) */
.studio-save-indicator { font-size: 9px; }   /* 保存状态 */
.studio-statusbar { font-size: 9px; }        /* 字数统计 */
```
窗口越小、信息越该清楚，这里方向完全反了，**且缩小字号违反 WCAG F80**。窄屏应该**隐藏次要项**，而不是把核心数字压到 9px。

## 四、量化基线（可直接作为改进后的对照）

| 指标 | 现值 | 判断 |
|---|---|---|
| 硬编码颜色 | **190 处 / 194 个值** | 缺 token 层 |
| token 引用率 | **27 / ~217 ≈ 12.5%** | 声明了但没用 |
| `transition` | **1**（在 `div` 上） | 缺动效层 |
| 交互元素有过渡的比例 | **0 / 66** | — |
| `@keyframes` | **0** | — |
| `:active` 选择器 | **0** | 缺按下反馈 |
| `cursor` 声明 | **0** | 连指针都不变 |
| `box-shadow` | **3**，全纯黑 | 缺深度 |
| 渐变/噪点/`backdrop-filter` | **0** | 纯平板 |
| 字号种类 | **17 种**（9–18、21–27 连续整数） | 没有刻度 |
| 字号 ≤10px | **43 处**（9px 有 9 处） | 中文不可读 |
| padding 取值 | **37 种**（0–25 每个整数都有） | 84% 不在 4px 栅格上 |
| `border-radius` | **10 种**，无层级逻辑 | — |
| `letter-spacing` | **3 处**（2 处是中文负字距，有害） | 缺字距系统 |
| `rem`/`em` | **0 处，100% px** | 不跟随系统缩放 |
| `!important` | **20 处，其中 14 处**只为抵消 `.studio-app button { border: 0 }` | 基础原语设计错误 |

## 五、另外发现两个必须尽快处理的问题

### 1. 旧稿引用了一个不存在的 CSS 文件 → 谁 import 谁构建失败

`Studio.tsx:13` 有 `import "./studio.css"`，而 **`src/features/studio/studio.css` 不存在**（已用 glob 确认）。

现在不会炸，只因为没有任何地方 import `Studio.tsx`。但这意味着：**旧稿那棵树不只"没启用"，而是"不可样式化"** —— `studio-toast`、`search-dialog-*`、`icon-button`、`studio-button`、`reference-chip` 等一整套类名在整个 `src` 里**没有任何 CSS 定义**。

### 2. 两套图标系统并存且不一致

| 文件 | 描边宽度 | 用途 |
|---|---|---|
| `Icon.tsx:36` | `1.6` | 活动路径全在用 |
| `StudioIcon.tsx:19` | `1.55` | 仅旧稿 + `SearchDialog.tsx` |

同一个名字（`book`/`map`/`search`/`link`/`arrow`…）**路径数据不同**。另外 `Sidebar.tsx:11` 的品牌月亮是**填充**的，而其他 26 个图标都是描边——品牌出现的地方恰好是图标语言唯一破例的地方。

## 六、建议的施工顺序

**原则：只动设计变量与状态层，不动布局与业务逻辑。** 每阶段独立可验收、可回滚。

| 阶段 | 内容 | 风险 | 收益 |
|---|---|---|---|
| **0** | **决定旧稿去留**（冻结或删除，统一到一套 Icon） | 无 | 不清掉它，任何 token 化都会被两套实现稀释 |
| **1** | 扩 token 层，把 190 处硬编码改引用。**像素级零变化** | 极低 | 之后每步都变成"改一个值" |
| **2** | 字体与排版（字体栈、11px 下限、行长下限、删负字距） | 低 | **视觉变化最大** |
| **3** | 动效层（1 条缓动曲线、四态补齐、面板用 transform） | 低 | **质变：从"截图"变成"软件"** |
| **4** | 深度（3 层带色调投影、1px 内高光、噪点覆盖） | 中 | 破掉平板感 |
| **5** | 状态与语义（修正 hover/选中倒挂、disabled、loading/empty/error、圆角层级） | 低 | 完成度 |
| **6** | 身份（把"编辑稿"的纸感做成一贯语言） | 中 | 决定上限 |

**最大单点收益：阶段 3 的动效层。** 从"1 处过渡"到"全站四态"，是性价比最高的一步。
**最容易踩的坑：跳过阶段 0。** 两套实现并存时改样式，等于在两个地基上盖同一层楼。
