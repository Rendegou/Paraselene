## M03a：原生出口核心

REAL：`llm-core::egress` 在 Rust 内保存运行归属、模型选择和最终序列化正文。dsh 提案没有空间、凭据、URL、headers 或额外上传字段。开始运行的可信宿主必须先验证用户/作品授权；后续请求不能自行改变归属或模型。

原生预览包含最终 HTTP 正文。确认只消费一次性 ID，不接收替代正文；五分钟预览 TTL、三十分钟运行 TTL 在操作时检查，结束运行撤销全部票据并中断在途传输。辅助摘要和标题与普通请求使用同一授权路径。单运行、单预览、单发送限制内存与并发；旧运行/旧发送的结束通知不能释放当前请求。

`AuthorizedCall::execute` 的取消覆盖连接与流式读取，逐事件检查也会丢弃已缓冲的迟到数据。接收端断开即停止。HTTP 客户端禁用重定向，直接发送冻结正文，不再 `.json()` 重建或追加元数据。生产调用方必须使用 DeepSeek 官方客户端；测试注入本地端点。

## 实际验证

云环境 Linux x64 / PowerShell 7.5.4 / Rust 1.99.1；Node 22 与 Windows 验收仍沿用各自独立范围。Rust 工具安装在工作区，不改系统或用户配置。

```powershell
$env:CARGO_HOME = "/workspace/tools/cargo"
$env:RUSTUP_HOME = "/workspace/tools/rustup"
$env:PATH = "/workspace/tools/cargo/bin:" + $env:PATH
cargo test -p paraselene-llm-core --locked
git diff --check
```

- Rust 单元测试：44 项通过，退出 0。
- 真实 loopback HTTP 集成测试：3 项通过，退出 0。
- 内容与模型服务均为 SIMULATED 合成数据，不含真实 Key 或私人语料。
- 关键断言：HTTP body 与预览逐字节一致；取消后不再发布已缓冲 delta/done；接收端断开停止收流；307 不携带正文与授权跳转；票据重放/跨运行错投/过期/关云/辅助请求旁路均被拒绝。

首次建立 Rust 工具链与依赖后，旧模型层 33 项测试通过；新增出口与集成测试后总计 47 项通过。`Cargo.lock` 未更新、未新增依赖。Windows Tauri、系统凭据、真实 API、dsh 受控 provider 与产品运行时接线尚未计为通过。
