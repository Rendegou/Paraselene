# M3 生产编辑器实施方案

日期：2026-10-16。状态：**草案，待用户审阅授权**。
依据：M3 spike 候选 C 可行性通过（`M3-C-20261015.md`），ADR-003 另估 12–20 人日。
本文件是方案说明，不是实施承诺；最终投入按实际验证调整。

---

## 1. 目标

把 M3 spike 的候选 C（自定义 raw UTF-16 编辑器）生产化，替代 M4 临时 `TextField`，
支持幻月小说客户端的核心编辑需求：

- 长章编辑（20 万字级）保持 P95 ≤ 50ms
- 中文 IME 组合输入稳定通过
- 段下线程槽位（thread slot）：在段落末尾嵌入讨论面板
- 装订线标记（gutter markers）：在行号侧显示讨论编号
- 引用装饰（reference decorations）：人名/地名高亮 + Ctrl+点击跳转
- 选区工具栏：非折叠选区时浮动"讨论这段"按钮
- 锚点映射：编辑时线程锚点随文本变化正确移动
- 撤销/重做、剪贴板、占位文案、热重配置

### 核心层次

| 层 | 职责 | 来源 |
|---|---|---|
| `EditorDocument` | 权威 raw UTF-16 正文、撤销/重做、组合分组 | M3 CWindowDocument |
| `EditorLayout` | 段落索引、增量排版、软分页分片、可见页准备 | M3 CLayout + CLayoutFrontier |

| `GutterMarkers` | 装订线讨论编号标记 | 新增，对标 editorMarkers.ts |
| `ReferenceDecorations` | 实体名高亮 + 点击跳转 | 新增，对标 referenceExtension.ts |
| `AnchorMapper` | 编辑时线程锚点偏移映射 | 新增，对标 threadModel.ts |

## 3. 分阶段实施

### Phase 1：核心编辑面（约 4–5 人日）

**目标**：把 M3 spike 代码从 `spikes/editor_comparison/` 迁入 `apps/desktop/lib/editor/`，
清理为生产质量，接入 `EditingSession` 保存链。

**工作项**：

1. **代码迁移与重构**
   - `CWindowDocument` → `EditorDocument`：保持 raw UTF-16 语义，增加持久化钩子
   - `CLayout` + `CLayoutFrontier` → `EditorLayout`：保持增量排版，清理 profile 代码
   - `CScene` + `CViewport` → `EditorScene` + `EditorViewport`：保持可见页绘制
   - `CNativeEditor` → `EditorInputClient`：保持全局 IME 客户端

2. **与 EditingSession 集成**
   - `EditorDocument.body` 变更 → `EditingSession.edit(body)` → `SaveCoordinator` 防抖保存
   - `EditingSession.adopt(loaded)` → `EditorDocument.replace(body)` + 清除撤销历史
   - `contentEpoch` 机制保留：只有外部重置才重写正文

3. **测试**
   - 迁移 M3 的 30 项测试（文档 11 + 排版 11 + 视口 8）
   - 新增 `EditorDocument` ↔ `EditingSession` 集成测试
   - 真实 Windows IME 复测（物理按键 `ni` 序列）

4. **验收门禁**
   - analyze/fmt 零问题
   - 全量 Dart 测试通过（含新测试）
   - 20 万字编辑 P95 ≤ 50ms（同机 profile）
   - 真实 Windows 拼音 IME 通过

**风险**：M3 spike 代码是隔离验证，可能有边界情况未覆盖。迁移时逐文件审查。

### Phase 2：段下线程槽位 + 装订线标记（约 3–4 人日）

**目标**：在编辑器内嵌入讨论面板入口，对标原 CodeMirror 的 `editorSlots.ts` + `editorMarkers.ts`。

**工作项**：

1. **ThreadSlot**
   - 在指定段落末尾插入一个 76px 高的内嵌 Widget 区域
   - Widget 区域是 Flutter Widget 的宿主（类似 React Portal）
   - 槽位身份按 `id` 稳定：讨论草稿更新不触发 Widget 重建
   - 槽位大小变化时通知编辑器重新排版

2. **GutterMarkers**
   - 在编辑器左侧装订线区域显示讨论编号按钮
   - 多个标记落在同一行时折叠为 "N+" 可展开菜单
   - 标记位置随编辑变化正确映射（前向/后向关联）

3. **AnchorMapper**
   - 每次 `EditorDocument` 变更时，计算所有活跃线程锚点的新位置
   - 严格文本等式验证：锚点文本不匹配时标记 `valid = false`
   - 撤销回冻结快照时恢复精确坐标

4. **测试**
   - 槽位插入/移除/切换不丢正文
   - 标记位置映射通过插入/删除/换行
   - 锚点验证：文本改变后 invalid、撤销后 valid

### Phase 3：引用装饰 + 选区工具栏（约 2–3 人日）

**目标**：实体名高亮和选区操作，对标 `referenceExtension.ts` + `ParagraphEditor.tsx`。

**工作项**：

1. **ReferenceDecorations**
   - 扫描可见段落中的实体名出现位置
   - 用不同背景色高亮（不重叠，先匹配优先）
   - Ctrl+点击高亮区域 → 回调打开实体详情卡
   - 实体列表变化时热重配置（不重建编辑器）

2. **SelectionToolbar**
   - 非折叠选区时在选区下方浮动工具栏
   - 显示字数 + "讨论这段"按钮
   - 选区滚动出视口时自动隐藏
   - 按钮 `preventDefault` 不抢编辑器焦点

3. **测试**
   - 实体名匹配与重叠解决
   - 工具栏位置跟随选区
   - 工具栏在不可见时隐藏

### Phase 4：生产化加固（约 3–4 人日）

**目标**：补齐生产环境需要的非功能性需求。

**工作项**：

1. **可访问性**
   - 屏幕阅读器基本支持（语义标签、角色声明）
   - 高对比度模式兼容

2. **持久化撤销历史**
   - 撤销栈按章持久化到 owned store
   - 重开恢复撤销历史

3. **边界加固**
   - 超长单行（> 10 万字无换行）的排版分片策略
   - 冷跳进未测量长段时的加载指示器（不阻塞 UI）
   - stress 滚动期间的帧率降级策略

4. **全矩阵验证**
   - 中文/英文/混排 IME
   - 100%/125%/150%/200% DPI
   - 窄窗口（800px）到宽稿（1920px）
   - 切章/切作品/确认/回滚后编辑器状态正确

## 4. 已知限制（从 M3 spike 继承）

以下限制在 M3 spike 中已记录，生产化阶段**不承诺消除**：

1. **stress 全幅滚动掉帧**：20 万字连续快速滚动时部分帧超 33ms 预算。
   这是懒测量架构的固有代价（不测量就不能精确画）。
   消除需要放宽"绝不画估计正文"的验收口径或后台 isolate 排版，
   两者都是产品契约/架构决策，不是简单优化。

2. **无换行长文档中段冷跳约 2.3s**：跳入未测量的超长段落需要同步排版前缀。
   有段落文本的普通跳转在 80ms 内。
   消除同上。

3. **原生 IME 认证不完整**：spike 只验证了拼音 `ni` 序列。
   完整认证需要覆盖：词组输入、候选翻页、Shift+方向键选区组合、
   全角/半角切换、中文标点等。生产化阶段逐步覆盖。

## 5. 投入估算

| Phase | 估算 | 置信度 | 说明 |
|---|---|---|---|
| Phase 1 核心编辑面 | 4–5 人日 | 高 | M3 spike 已有完整实现，主要是迁移和集成 |
| Phase 2 线程槽位+标记 | 3–4 人日 | 中 | 需要新增，但 CodeMirror 端有完整参考 |
| Phase 3 引用+选区 | 2–3 人日 | 高 | 相对独立，不影响核心编辑器 |
| Phase 4 加固 | 3–4 人日 | 中 | 可访问性和持久化工作量不确定 |
| **合计** | **12–16 人日** | | 在 ADR-003 的 12–20 人日估算范围内 |

按用户要求"不着急"，实际节奏可以按 Phase 逐步推进，每个 Phase 完成后验收再进入下一个。

## 6. 不做的事

- **不接真实模型调用**：编辑器只负责文本编辑和线程 UI，DeepSeek 接线是 M7+ 的事
- **不接作者数据库**：编辑器使用合成库或 owned-synthetic 库验收
- **不做富文本**：幻月正文是纯文本（Markdown 导出时转换），不需要 bold/italic 等样式
- **不做多窗口/多视图**：单窗口单章编辑足够
- **不修改 Rust 核心**：编辑器的所有数据通过 `WorkspaceRepository` 接口访问

## 7. 决策点

以下问题需要用户确认：

1. **Phase 顺序**：建议严格按 1→2→3→4 顺序，每阶段验收后再开始下一阶段。
   是否同意？

2. **Phase 2 优先级**：段下线程槽位是幻月的核心差异化功能。
   如果时间紧，可以先做 Phase 1+2，Phase 3+4 延后。

3. **已知限制接受**：stress 滚动掉帧和中段冷跳是否接受为已记录限制？
   如果不接受，需要额外投入探索后台排版或估算绘制方案。

4. **spike 代码处置**：M3 spike 代码在 `spikes/editor_comparison/`。
   迁入主代码后，spike 目录保留为历史参考还是删除？
