# 任务合同模板

适用于本仓库中等以上改动；小改动直接在当前任务描述填相关字段即可。跨会话/多批次任务保存到 `docs/tasks/` 并在[当前状态](../progress.md)登记。流程见[Agent 工作流](agent-workflow.md)，需求编号见[产品目标](../product-scope.md)。

## 身份与目标

- ID / 名称 / 状态 / 当前负责人或会话：
- 关联需求（W01–W07；纯工程任务注明工程目标）：
- 源码基点与既有差异：
- 用户完成后能够做什么；可观察的成功条件：
- 本轮非目标与不能退化的不变量：

## 范围与复用依据

- 允许修改的页面、组件、协调器、测试与文档：
- 现有实现/设计角色/状态样例/测试入口；允许的视觉差异：
- 依赖、原生、存储、作者数据/外发等边界；需要决策的真实冲突：
- 多人/多 Agent 协作时的文件和 SDK/构建所有者；单人任务无需另造角色：

## 行为与状态合同

每个适用场景按“前置状态 → 用户动作/异步结果 → 可观察预期”描述。考虑正常、加载、空、失败、重试、忙碌、取消、迟到响应、身份/版本切换和长内容；不适用项注明原因。

UI 任务同时注明窗口/字号/语言、真实命中、键盘/焦点恢复、IME、语义、减少动态效果及正文/草稿保留的相关组合。不要用“界面完善”“通过所有测试”替代具体预期。

## 验证与完成条件

- 受影响的行为断言、实际操作、命令与工作目录：
- 切片结束所需的静态/全量/UI/FFI/原生验证及环境：
- 需要当前人工或系统证据的项目；未测时允许声明的完成范围：
- 若目标不能满足，保留哪些数据/界面与恢复入口，记录什么缺项：

验收以可观察行为和数据不变量为主；禁止删除断言、放宽合同、忽略真实命中警告或自动重批基线换绿。

## 交付记录（实施后填写）

- 实际改动与实现状态：
- HEAD / 工作树范围或源码指纹 / 工具与产物版本：
- 实际命令、退出码、计数、过滤范围及证据：
- 复核结论；当前 FAIL / NOT_RUN / SKIPPED：
- 当前进度条目、下一动作与恢复/回退说明：

实现、适用范围已验证、发布批准分别记；尚未执行的项目保留未执行状态。已获授权的常规动作不重复请求许可，实质冲突写明具体来源。
