## F1 / P1：正文 IME 组字没有被全局快捷键守卫保护

位置：`apps/desktop/lib/workspace/presentation/manuscript_editor.dart:579–580`，关联 `_focusedEditable:560–567`。

当前守卫只从焦点祖先查找 Flutter EditableText 的 composing。正文是自定义 EditorViewport/InputClient，没有 EditableText 祖先，因此正在组字的正文也得到 composing=false。旧路径对 client.composing 的检查在新实现中遗漏；事件随后进入 Ctrl+F 或 Escape 分支。

独立复现：

1. 挂载真实 WorkbenchScreen 与合成仓库，令正文 EditorInputClient 的 composing 为 `TextRange(0,1)`，断言 client.composing=true。
2. 按 Ctrl+F：查找栏仍打开，出现“下一处”；预期应把组合期间按键留给输入法。
3. 在专注模式同样设正文 composing，再按 Escape：侧栏恢复，专注被退出；预期只处理输入法组合，不能退出工作台层级。

两项探针均失败。这里证明的是 Dart 事件路由已错误；没有宣称本轮实测了真实拼音丢字。

整改方向：全局处理任何查找/保存/层级退出前同时校验自定义正文 client.composing 与当前 EditableText 的非空组合范围；组字期间不能让快捷键分支改变焦点或布局。补入正式快捷键回归。

## F2 / P1：收起讨论销毁生成状态，重开后不能取消仍在运行的请求

位置：`apps/desktop/lib/cowrite/discussion_panel.dart:53–57`、`272–275`，关联 `apps/desktop/lib/editor/editor_discussion_overlay.dart:79–96`。

生成状态、operation ID、work ID 和取消标记仅存在 DiscussionPanel State 中。新单槽布局在 height=0 时不再挂载面板，所以收起/切换线程会 dispose 这些状态；再次展开创建新 State，_running=false，取消按钮消失，预览按钮重新启用。原 send Future 仍继续运行，收起没有取消它。

独立复现：

1. 使用实现 GenerationRepository 的本地假仓库，在真实工作台创建选段线程并输入指令。
2. 打开完整预览，明确确认后让 send Future 保持未完成；断言 sendCalls=1、“取消生成”存在。
3. 点面板关闭，再从原标记展开同一线程；断言收起未调用 cancel。
4. 旧 send 仍挂起，但新面板找不到“取消生成”，预期的取消入口断言失败。

整个流程零外网、零凭据。问题是可取消请求的生命周期与 Widget 挂载生命周期被混在一起；仅持久保存草稿不能解决。

整改方向：将每个 work/document/thread/operation 的在途状态与取消句柄放到 Registry/生成业务接缝，由所有面板读取同一状态；收起只改展示，重新打开继续展示进度和取消，不能重新启动同一在途请求。

## F3 / P2：资料“带入讨论”忽略当前展开的选段线程

位置：`apps/desktop/lib/workspace/presentation/lore_preview.dart:165–171`，关联 `workbench_sidebar.dart:_attachLoreEntry`。

attachLoreReference 无条件调用 registry.chapterThread()；loreEntryAttached/removeLoreReference 也只读取整章线程。当前展开线程 ID 只在 ManuscriptEditor 中管理，侧栏没有获取它。作者正在就地讨论某个选段时，从资料预览点“带入讨论”仍会新建/修改整章线程，当前选段请求得不到作者选中的资料。

独立复现：创建并从标记展开有效选段线程，执行侧栏实际调用的 attachLoreReference(registry, entryId)，该选段线程 attached 仍为 []，断言失败。生成预览实际读取的是当前选段 thread.snapshot['attached']，因此资料不会进入该选段请求。

R09 要求仅在没有活动线程时按整章规则处理；当前实现把这一回退写成了所有情况。现有 helper 测试验证了“始终整章”的实现，没覆盖工作台当前活动线程。

整改方向：给展示层提供明确的当前讨论目标，预览打开时绑定并在操作时校验 work/document/thread；带入、移除、已附加状态均针对同一目标。仅无活动线程时使用整章回退。

## F4 / P1：包验证默认按通配符删除旧目录，缺少归属和保留清单

位置：`scripts/verify-m1-bundle.ps1:59–64`。

验证 PASS 后默认枚举所有 m1-distribution-* 目录，按 CreationTime 留一个，其余直接 Remove-Item -Recurse -Force。它没有核对这些目录是否由本脚本创建、是否唯一失败现场/回退包、manifest/保留台账或整树链接；只检查路径字符串在 build 内。该逻辑会在普通验证时自动触发，不是显式清理命令。

非破坏性复现：在审查专用 fixture 中创建一个含唯一合成诊断文件的 m1-distribution-manual-keep 目录和一个更新的模拟副本，仅运行相同候选表达式。结果 WouldDeleteUnmanagedDirectory=true，实际删除 0。由此证明只凭前缀/时间就会选择归属不明目录；未尝试在真实 build 根执行删除。

这不符合原清理方案“未列路径默认不在白名单、失败现场保留至诊断、逐包核验后收敛”的边界。

整改方向：验证与清理分开；自动收敛只能处理带明确所有权标记、已登记为可淘汰且不在保留集的精确路径，并在执行时重新核对全部边界。未知、失败、加载中或含未验证链接的目录保持不动。
