## 对幻月的设计结论

- 第一视觉问题是**信息架构**：当前卡片三个标签页、多个字段、说明文字同权重排列，像缩窄的设置页。先让“写一句”成为默认页唯一主任务，空间与发送边界退居辅助位置。
- 第二视觉问题是**角色本体**：当前 SVG 月亮/星星/云朵像通用图标，缺少可以识别的剪影与材质。三种形象需要一套自有角色语言，并在 120px 下读得清。
- 第三视觉问题是**装饰误用**：横线输入框、轨道星点、页脚口号增加了手帐符号，却没有形成真实的层级。删掉无功能装饰，把温暖用在正文、插画和确认动作。
- 设置应保持专业、可扫描。Key 状态、四空间开关、模型、运行计数按频率与风险排序；分享包收入形象页的次级区。
- 参考只提供设计方法。所有产品文案与状态仍以本仓库已实现能力为准。

## 2026-09-27 视觉复核：Clawd on Desk 内置宠物

用户指出前述 31 项调研偏重仓库文字，没有充分检查桌宠实物。已用用户提供的 Clawd on Desk 主题页截图复核三个**内置**宠物，并核对[项目 README 的动画展示](https://github.com/rullerzhou-afk/clawd-on-desk#animations)、[Calico 主题状态配置](https://github.com/rullerzhou-afk/clawd-on-desk/blob/main/themes/calico/theme.json)与[Cloudling 主题状态配置](https://github.com/rullerzhou-afk/clawd-on-desk/blob/main/themes/cloudling/theme.json)。此前检查本机 Doro/Roxy 导入主题是误解用户所指，不能算作这次内置宠物复核。

- **Calico**：耳朵、橘色块、尾巴、低矮四足形成完整剪影；白脸、深色眼睛、少量腮红在主题卡中仍清楚。主题配置包含 idle、思考、工作、睡眠、拖动、被戳与 mini 状态，形象是为动作而画，不只是独立头像。
- **Clawd**：像素蟹只有橘色块、方眼、短脚和横向钳形，缩小后仍能一眼识别；说明辨识度来自轮廓与比例，不靠五官复杂度。
- **Cloudling**：轮廓几乎是一团白云和一对蓝眼，静态结构极简，动态状态与表情让它成立。它的简洁有清楚的造型规则，不等于把普通几何形状加上脸。
- **幻月要吸收的方法**：在约 120px 的使用尺寸先验剪影、身体/耳/尾是否支撑动作，再定表情；同一角色的月、星、云外观应保持一致骨架，只改受控特征。漫画参考提供夸张的半眯眼与反差表情，不应把漫画角色的具体头饰或服装搬进宠物。
- **版权边界**：项目 README 将 Clawd、Calico、Cloudling 的角色美术分别标为权利归属明确的素材；这里只研究设计方法，幻月素材必须原创，不复制、改色或拼接这些图片。

### 对照幻月现状

Clawd on Desk 的 [Calico 主题配置](https://github.com/rullerzhou-afk/clawd-on-desk/blob/main/themes/calico/theme.json)不仅列出待机、游走、思考、工作、睡眠、醒来等素材，还给拖动、点击反应和迷你模式单独设资源；它用 `contentBox`、`baselineY` 与不同状态的命中范围维持角色位置和可点区域。[Cloudling 主题配置](https://github.com/rullerzhou-afk/clawd-on-desk/blob/main/themes/cloudling/theme.json)也把动态 SVG 状态当作角色本身的一部分。因此“有设计感”同时来自造型和状态的一致性。

幻月当前 `src/App.tsx` 每种外观只有一张静态 PNG；`src/App.css` 只给整张图做悬停平移和按下缩放。点击立即打开卡片，拖动依靠顶部横条，尚无待机呼吸、睡眠、唤醒、注视或可见的点击反应。三张现用兽形图已被用户否定，不能把功能可用视为角色验收通过。

下一轮角色实现按以下顺序验收：① 主造型先由用户确认；② 在真实 120 × 120 桌面窗口检查轮廓、脸和足部；③ 同一骨架完成至少待机、被点、睡眠三个姿态，并维持统一基线和透明边界；④ 再扩展星/云外观。动作优先改变眼、耳、尾和身体重心，不用弹跳整张静态图代替角色表演。状态数量按幻月的实际交互逐步增加，不照抄 Clawd 的主题清单。
