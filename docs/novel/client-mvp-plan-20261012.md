# 幻月：从界面 Demo 到最低可用 Windows 客户端

日期：2026-10-12，进展更新 2026-10-13。状态：**A 原生出口 PARTIAL；B 正式作品/保存已实施，原生验收进行中；C/D 未实施**。执行证据见 [CLIENT-MVP-A](../evidence/CLIENT-MVP-A-20261012.md)、[B 接线](../evidence/CLIENT-MVP-B-20261013.md)及[存储验收](../evidence/CLIENT-MVP-B-STORAGE-20261013.md)，去重清单见 [合并审查](client-mvp-review-20261012.md)，B 合同见 [数据适配](client-mvp-data-contract-20261012.md)。

本轮目标是让作者真的能使用幻月完成一小段创作：打开自己的作品，可靠地写下并保存正文，引用设定与 Agent 共写，审阅后采纳，再关闭并重启继续写。保留已经确定的暖白正文、浅灰外框和段下共写方向，下一轮以真实操作、数据可靠性和 Windows 客户端行为为主。

此前 `FRONTEND_PASS` 只表示合成场景的前端验证通过，**不代表项目已最低可用**。其他 Agent 可按本文补充缺陷和实现清单；本文中的代码核查事实、用户报告与待验证假设分开记录。

## 1. 最低可用的范围

第一版只交付 Windows 桌面客户端。浏览器继续用于开发和合成场景评审，不承担正式作品存储或产品发布。保留 React、CodeMirror 6、Tauri 2 与现有 Rust / SQLite 内核。

最低可用必须同时满足：

1. 作者能新建、打开、切换自己的作品与章节，不依赖《雾海来信》或旧桌宠入口。
2. 正文与资料可以编辑、保存和重启恢复；保存失败、冲突与未保存内容明确可见。
3. 章节至少支持新建、重命名、调整顺序；能查找正文。删除先采用可恢复归档，不把永久删除加入首轮。
4. 人物、地点和世界规则可保存、引用、定位出处；没有出处时明确为空，失效时不乱跳。
5. 段落讨论的未发草稿、引用和记录可恢复；切段、切章、切作品不混淆。
6. 配置作者自己的 DeepSeek Key 后，至少一条“引用设定 → 请求改写 → 真实候选 → 作者采纳”路径完整可用。
7. 未配置 Key 或网络不可用时仍能离线写作、查本地资料和导出；模型故障不影响正文保存。
8. 导出使用系统保存对话框，可取消、可选择位置，成功和失败都有准确反馈。
9. 安装后直接启动应用，无需打开终端、开发服务器或浏览器；窗口、中文输入、快捷键、退出和重启符合 Windows 使用习惯。
10. 用安装后的同一构建跑通本文末尾验收脚本，发布阻断项全部关闭。

首轮不扩展多模型、自动世界推演、自动画地图、插件市场、云同步、协作编辑、自动更新、复杂排版导出或百万字最终性能承诺。地图先保证地点资料与引用可用；自由编辑地图位置若尚无可靠存储，明确延后或设为只读。保留现有视觉识别，不重新开展一轮主题设计。

## 2. 已确认的 Demo 缺口

以下来自当前代码与已有验收记录，不是新一轮原生运行结论。

- **正式作品没有接入新工作台。** 活动入口是 `src/features/studio/StudioApp.tsx → writing/NotebookApp.tsx`；状态仍由 `useStudio` 与预览 DTO 提供。旧正式保存、版本和设定业务位于 `src/features/novel/`。
- **当前保存仍是浏览器预览保存。** `usePreviewPersistence.ts` 使用 localStorage、450ms 延迟与 pagehide；这不能证明原生窗口关闭、异常退出或安装包升级时的作品恢复可靠。
- **Agent 按钮没有真实生成闭环。** `writing/useThreadRequests.ts` 只把要求加入记录；`useThreadCandidates.ts` 调用示例 `makeSuggestion`，任意选段可能得到待手工填写的候选。当前动作不能当作模型完成。
- **共写记录刷新就丢。** `writing/useThreadStore.ts` 的线程、草稿、引用、记录和候选保存在 React 内存；“版本”是会话列表，不能替代已有正式版本树。
- **导出仍是网页下载。** `projectActions.ts` 使用 Blob、临时链接和 `download`，没有客户端文件路径、取消、覆盖及写入错误流程。
- **一些文案与内容写死。** `NotebookManuscript.tsx` 与 `NotebookSidebar.tsx` 写死“第一卷 · 海雾来时”；正式入口仍带“示例作品／预览”文案，目录里还有开发用项目框架。
- **标题本身一直是输入框。** `NotebookManuscript.tsx` 用常驻 `<input>` 显示章节标题；点击它产生较大输入光标属于当前实现行为。下一轮改为明确的重命名状态，避免把展示文字都做成隐形输入框。
- **正式入口与窗口身份需要适配。** 旧 `open_novel_editor` 会打开或复用名为 `novel` 的旧窗口，并维护 selected workspace；新默认窗口是 `studio`。不能直接调用旧入口后又跳回旧工作台，必须统一新窗口的作品选择和生命周期。
- **原生新界面验收缺失。** 上轮浏览器验证与30个领域测试不覆盖 Windows WebView2 的 IME、系统文件对话框、关闭前保存、凭据管理器和安装后离线运行。

复用入口：`src/features/novel/state/` 的按章加载、自动保存、恢复与目录动作；`diff/` 的 patch 审阅；`lore/` 的设定和版本出处；`src/lib/ipc.ts` 的 working copy、patch、版本、设定与外发预览契约；Rust 的 `memory-core / novel-core / llm-core`。代码存在只说明值得复核，不直接继承历史 PASS。

## 3. 专项：异常光标、横条与网页感

用户报告：点击部分组件会出现像输入光标的横条，大小不一。**尚未完成逐项复现，不能把所有现象都归因于 CSS。** 常驻标题输入是已确认的一处；其余需在实际客户端中定位。

审查时先区分四种现象：鼠标 I 形指针、文本插入 caret、文字选中效果、键盘焦点轮廓。记录点击位置、前后焦点元素、是否处于编辑状态、原生/浏览器环境、DPI 和截图。排查浏览器 caret browsing、WebView2 默认行为与应用代码时保持这些类别分开。

交互规则：

- 正文、正在编辑的标题/设定、搜索与共写输入允许文本光标；标题与资料展示默认是阅读状态，作者主动重命名或编辑后才进入输入状态。
- 目录项、工具栏、页签、图标、按钮、卡片标题与空白区域不产生文本插入光标，也不因普通点击意外选中文字。
- 普通正文可以选择和复制。只读资料、候选与历史文字仍可复制；操作 chrome 限制文本选择，不对整个应用设置 `user-select: none`。
- CM 段下区域保持 `contenteditable=false`；它内部明确的输入框可以输入。点击空白、切换页签、开关资料卡不能把正文 caret 留在组件之间，或生成跨整个共写块的大光标。
- 键盘焦点轮廓保留且清晰；鼠标点击的表现克制。不能通过全局隐藏 caret、取消所有 outline 或拦截所有 mousedown 来掩盖问题。
- 同时验证文本选区、拖选、双击选词、中文组成输入、菜单焦点回归和 Ctrl+Z，防止“去网页感”破坏编辑器。

重点文件：`StudioBase.css` 的根级 `user-select: text`；`NotebookTheme.css` 的 caret / cursor / focus 样式；`NotebookManuscript.tsx` 的标题输入；`ParagraphEditor.tsx`、`editorSlots.ts` 的可编辑边界；共写、资料卡与菜单的事件处理。它们是调查入口，除常驻标题输入外不视为已证实根因。

其他客户端工艺要求：

- 保留 Windows 原生标题栏、最小化、最大化与关闭，首轮不造第二套窗口控制。尺寸、DPI、最大化与最近窗口位置有一致行为。
- 首次启动展示“新建作品／打开作品／最近作品”，可选进入示例；正式工作区不展示合成场景切换、示例候选、开发框架或无意义的预览提示。
- 开发框架移至帮助/开发入口；默认设置只保留作者需要的版式、模型连接与本地数据位置等信息。
- 菜单能用键盘打开、移动、选择和关闭；Escape 逐层关闭最上面的弹层，不清空草稿。资料卡与重命名结束后回到原输入和原选区。
- 基础快捷键与正文右键复制/粘贴可用；浏览器导航、刷新和开发工具行为不能侵入正式客户端流程，也不能抢占中文输入法。
- 文件操作用系统对话框；外部参考/帮助主动交给系统浏览器，不把网页导航塞入正文窗口。
- 错误提示持续到作者处理，有重试、保留草稿或导出等实际动作；短暂 toast 只用于不影响内容安全的反馈。

## 4. 四个顺序交付，不再展开大功能树

### A. 客户端交互基线

交付：新工作台在真实 Tauri 窗口可运行；点击/选择/焦点/IME规则成立；清理开发入口与展示输入混用；系统导出入口和快捷键策略明确。

先复现用户所说的大小横条，按组件修复；检查加载、空态、禁用、错误与窄窗口。确认窗口尺寸政策：当前原生最小760×560，414px只是开发时的紧凑布局检查，不能据其截图宣称客户端支持414px窗口。检查100%/125%/150% Windows DPI与最大化。

出口：原生端完成“打开应用 → 编辑正文 → 打开共写 → 查资料 → 回到正文”，没有误输入、跨块caret、丢焦点或无法关闭弹层。此时仍可用隔离测试数据，不宣称正式保存完成。

### B. 自己的作品与可靠保存

交付：新建/打开/最近作品，章节新建/改名/重排，正文查找，working copy 保存与恢复，人物/地点/世界规则保存，原生导出。完成后先形成可用的离线写作工具。

通过领域适配层接旧内核；目录加载摘要，正文按章读，避免继续把整部作品塞进预览全局 state。正式与示例数据源显式隔离，正式读取失败不能悄悄换成示例并写回。预览稿转正式作品只提供作者主动执行的一次性导入，可先导出备份，不能自动覆盖旧库。

保存状态绑定正在保存的具体 revision。切章、切作品、关闭窗口前处理待保存内容；失败提供取消切换/退出、重试和导出。正常关闭要等待已提交写入完成；异常退出至少恢复最近一次成功保存的版本，并能识别更近的恢复稿。对“正在保存”状态不保证尚未提交字符已经落盘，必须在验收中检查实际丢失边界并修正。

建立最小持久共写存储：作品/章节/线程ID、目标快照与版本、未发草稿、引用快照、请求状态、模型输出和候选绑定。若现有库无对应能力，先确认差距，再添加最小迁移及旧库升级/重开测试；正式作品版本继续复用已有系统。记住最近章节、版式和滚动位置，不把它们混入正文。

出口：作者输入正文与资料，立即切章、正常关闭、重启均能恢复；保存冲突不覆盖；导出失败不报成功。此出口通过前不开始大规模真实生成接线。

### C. 真实段落共写与资料引用

交付：Key设置、真实请求、明确上下文、响应/候选、取消与失败恢复、作者采纳、会话撤销及重启后的版本回退。首轮先做好局部改写，全章入口用于同一套讨论，不展开额外自主规划能力。

Key继续经Rust存入Windows凭据管理器，不回显明文、不进日志或localStorage。作者先看到此次将发送的选段、章节上下文与资料，通过已有外发预览/确认契约发起请求；未配置Key、Key无效、凭据存储失败、离线、超时与限流分别有可执行状态。

“记录要求”与“发送给Agent”必须区分；正式工作区不能用示例对白伪装响应。请求绑定作品、章节、线程、正文revision/版本与operationId。切章/切作品、重复点击、重试、取消后，旧响应只进入其所属线程或被标记过期，不污染当前正文。若已有小说生成接口不支持新线程/流式/取消，仅在适配层补齐契约，不把已有SSE代码存在视为取消已接好。

候选先保留为候选。正文变化后继续保留旧候选并标记过期；后端核对版本后才允许采纳。重复采纳幂等，采纳只写编辑稿，确认正稿仍是作者明确动作。会话内撤销使用编辑器历史；重启后回退使用已有持久版本/恢复契约，不能承诺CodeMirror内存历史跨重启存在。

正式出处绑定作品、文档、不可变版本与字符范围，适配UTF-16/Unicode计数；新稿变化时提示旧出处，提供查看绑定版本/定位当前稿等明确动作，不靠相似句猜位置。资料“带入当前讨论”必须确实改变可见的发送上下文。

出口：使用作者明确授权的小型测试作品和Key，真实生成一份局部候选，采纳/拒绝、取消、过期拒绝与重启恢复跑通。没有真实调用证据，完整AI客户端状态仍为PARTIAL；人工写作功能可以单独标记通过。

### D. 安装后的最低可用验收

交付一个Windows x64安装产物与验收记录；安装后的构建与验收构建一致。首次启动不预置作者私人作品，不自动发模型请求。无开发服务器时正文、资料、字体与保存可靠；在线只影响模型任务。

在安装版复跑核心流程、IME、系统文件对话框、关闭/异常退出恢复、Key存储错误和升级数据保留。其他Agent发现的发布阻断项关闭后，再把产品状态改为 `CLIENT_MVP_PASS`。

## 5. 接线约束与最小工程边界

依赖方向保持：新UI → 按领域的hook/适配器 → `src/lib/ipc.ts` → Tauri薄命令 → Rust核心 → SQLite或官方模型服务。

- SQLite是正式数据权威；localStorage只保留显式开发预览。不要直接把 `StudioProject` 整体JSON当正式作品库。
- 新UI与旧DTO映射集中在适配层；组件不直接使用Tauri API，也不重新实现版本树、patch安全校验或凭据系统。
- 正文保存、线程保存和生成状态独立；模型失败不能堵塞正文保存。写入有事务、revision和幂等边界。
- 线程显示锚点可随事务映射；生成快照不变。失效记录可读、可重新指定目标，不能静默丢失。
- 数据迁移只补经核实缺少的最小结构；旧库升级、失败、重开与回退策略写清楚，不清库重来。
- 既有安全、正稿/候选隔离和外发确认边界保留；不通过放宽CSP/IPC权限或隐藏错误推进验收。

当前不是要求重做所有页面。先把真实路径打通，再按缺陷清单逐项收口；没有明确作用的控件撤下或禁用并说明原因，不能留下看似能用的空动作。

## 6. 给其他 Agent 的审查任务

此次由其他Agent先列细节、补证据，**不要求它们立即改代码或重新设计主题**。按以下四个视角分别检查，最终合并到一份清单：

1. **客户端交互**：逐组件检查caret、选择、焦点、键盘、IME、菜单、弹层、DPI、窗口与系统文件流程；优先复现用户报告。
2. **数据闭环**：作品与章节入口、保存/恢复、切换/退出、备份、线程持久化、资料与地图数据；对照旧内核找可复用与缺失项。
3. **Agent与引用**：真实发送/取消/重试、上下文可见、Key状态、候选绑定、采纳/回退、出处版本、跨章/跨作品隔离。
4. **发布验收**：Windows安装版、离线运行、原生能力、升级数据保留、已有自动检查是否真的覆盖新流程。

每条发现采用同一格式，不要只写“优化体验”或“完善细节”：

```text
编号：MVP-001
范围：客户端交互 / 保存 / Agent / 引用 / 发布
证据级别：原生复现 / 浏览器复现 / 代码确认 / 待验证假设
优先级：P0 / P1 / P2
对应阶段：A / B / C / D
位置：页面 + 组件 + 文件/行号
复现：起始数据、动作、实际结果
预期：作者应该看到或完成什么
影响：是否阻断创作，是否存在绕过方法
建议：最小修正、复用入口与依赖；根因未明时写调查步骤
验收：具体动作与断言、原生/浏览器环境、必要故障案例
状态与负责人：待确认 / 待实施 / 待验收 / 已关闭；认领时填写
```

P0：数据丢失、静默覆盖、写入错误作品、误采纳、敏感材料误发或主流程完全不可达。P1：最低可用必需能力缺失/不可用、原生输入与焦点严重异常、关键错误无恢复方式。P2：不阻断最低可用的工艺改善与增强项。客户端最低可用要求范围内P0/P1清零；P2不得趁机扩展成新的主线。

“需要真实接线”和“已有实现存在缺陷”分开写。待验证不能报成确认缺陷；同一根因影响多个控件时合并主项并列出范围。同一任务一个负责人，合并清单后再认领实施，避免多个Agent同时改共享状态与IPC。

可直接发给其他Agent的任务：

## 7. 最终验收脚本

在安装后的Windows客户端使用合成作品执行，记录构建标识、系统版本、WebView2版本、DPI、实际命令/操作和结果：

1. 冷启动 → 新建空作品 → 新建两章 → 重命名/调整顺序 → 正文查找；正式界面没有固定示例标题。
2. 输入中文、换行、emoji，跨段选择；用微软拼音组成输入和候选窗，验证中文标点、退格、快捷键与焦点回切。
3. 逐一点击目录、页签、工具、卡片标题和空白，验证无意外caret/选字；主动编辑时caret正常，键盘焦点仍可见。
4. 写正文 → 保存中切章 → 回来 → 正常关闭 → 重启，核对正文和状态。模拟保存失败/版本冲突，验证保留草稿、取消退出与重试。
5. 模拟异常退出，核对最近成功保存版本与恢复稿，记录未提交字符的实际恢复边界；不以“没有崩溃”替代恢复断言。
6. 创建人物、地点和规则 → 建立出处 → 打开卡片/深入/定位 → 回到原输入；正文删改后出处失效不会跳到相似句。
7. 两处段落分别写未发要求、带入不同资料 → 切章/作品 → 返回 → 重启，草稿和绑定正确、只有一个展开区。
8. 未配置Key/断网时继续写作与导出；配置授权Key后查看材料并真实发起一次局部改写。
9. 生成中切章、取消和重试；返回原线程核对输出。修改正文再采纳旧候选必须拒绝；双击采纳只执行一次。
10. 采纳、拒绝、继续调整、会话撤销、确认版本与重启回退；原稿、候选和正式版本关系清晰，讨论不混入正文。
11. 系统导出对话框：选择路径、取消、已有文件覆盖、不可写位置；打开导出文件核对内容，失败不报成功。
12. 100%/125%/150%DPI、1440×900/1280×800、最小窗口与最大化下检查；长目录、长标题、长讨论不遮挡正文和主要动作。用一部合成10万字/50章作品检查按章加载、输入、查找与切换，记录性能而不虚报百万字稳定。
13. 退出客户端、关闭开发服务器，再启动安装版；检查离线字体、存储、最近作品与窗口恢复。升级测试构建后数据仍可读。

自动检查沿用 `scripts/check-quality.ps1`，按变更面执行类型、构建、领域行为、IPC边界、TS/Rust复杂度和必要Rust测试；原生能力必须另有实际操作证据。缺Key、缺环境、未运行分别记录，不能把过滤、mock或未测项计为通过。
