# 让 AI 生成的前端"没有 AI 味"：诊断与施工手册

日期：2026-10-13。对象：`paraselene-work` 的 Studio 工作台（`http://127.0.0.1:1422/` 的 `vite preview` 产物）。
状态：**只诊断，未改任何产品代码**。本手册是施工前的判断依据，不是已完成的工作。

---

## 0. 先给结论

"AI 味"不是一种配色或一种字体，而是**一堆可以被逐条列举的默认值**。模型在没有被指定时，每次都回退到同一批默认值；这些默认值单独看都不难看，叠在一起就产生了强烈的同质感。

关键判断：**这个项目的 AI 味来源和大多数人以为的不一样。**

它没有紫蓝渐变，没有 Inter，没有 `rounded-2xl` 白卡片，没有三栏特性网格。它的配色（冷灰底 + 暖白纸面 + 淡青绿强调）其实是有判断的。它看起来仍然"像 AI 做的"，是因为四个更隐蔽的原因：

1. **零动效**。五个样式表、全部交互元素，只有 1 处 `transition`。
2. **没有设计变量层**。约 30 个手写十六进制绿色、多个色族的灰混用，没有 token。
3. **没有深度**。投影只有 2 处，且都是纯黑低透明；没有纹理、没有层次、没有光源一致性。
4. **排版没有尺度**。中文界面里出现 9px 标签，字重只用 400/500/600，全项目只有 2 个 `letter-spacing`。

也就是说：**它的问题不是"用了 AI 的默认审美"，而是"从来没有被排版过"**。这反而是好消息——第 5 节的施工顺序里，前四步都是低风险纯样式改动。

## 1. 为什么"AI 味"可以预测

模型输出的收敛性来自三个可预测的机制，理解它们才能对症下药：

- **默认值坍缩（default collapse）**：指令越抽象（"做个好看的写作工具"），模型越必须从训练分布里取最高频的那个解。高频解 = 大家都见过的样子 = 没有辨识度。
- **训练数据同质化**：主流 UI 训练语料被 Tailwind 模板、shadcn 默认主题、Dribbble 流行样式主导。模型的"好看"实际上是 2021–2024 年网络模板的平均值。
- **约束缺失时无法产生"取舍"**：真正有设计感的界面，其质感来自**刻意的取舍**（这里不要边框、这个字号要小得刚刚好、这个动效必须是 180ms 而不是 300ms）。模型在无约束时会选择"处处都还算合理"的中庸解，而中庸解的集合就是 AI 味。

推论：**去 AI 味的本质是注入约束，而不是注入装饰。** 把 20 个决策写成 token，比让模型"再精致一点"有效一个数量级。

## 2. 两类 AI 痕迹

### 2.1 一类：显性套话（这个项目基本没有）

这些是最容易被识别的，也是最容易修的。列出来是为了确认本项目不在此列：

| 痕迹 | 典型形态 |
|---|---|
| 紫蓝渐变 | `from-indigo-500 to-purple-600`、`#6366f1`→`#a855f7` |
| Inter 万能字体 | 全站 Inter，无中文适配 |
| 卡片套话 | 白底 + 1px 灰边 + `box-shadow: 0 1px 3px rgba(0,0,0,.1)` + `rounded-2xl` |
| 三栏特性网格 | 三个等宽等高的 feature card，图标在上、标题居中 |
| emoji 当图标 | 🚀 ✨ 🎯 直接出现在标题或按钮里 |
| 玻璃拟态滥用 | 到处 `backdrop-filter: blur(20px)` |
| "魔法棒"生成图标 | 星芒 / 闪光是 AI 功能的固定符号 |
| 文案套话 | "Elevate"、"Seamless"、"释放创造力"、"让创作更高效" |
| 空状态敷衍 | 一个灰色图标 + "暂无数据" |
| 全居中对称 | 所有区块居中，没有非对称或出血 |

### 2.2 二类：隐性工艺缺失（**这才是本项目的问题**）

这类痕迹不会让人说"这是 AI 做的"，而是让人说"说不上来，就是不对劲"。逐条对照本项目：

| # | 工艺缺失 | 本项目实测 | 为什么读起来像机器做的 |
|---|---|---|---|
| 1 | **无动效层** | 5 个样式表全文只有 **1 处** `transition`（`.studio-map-canvas`）；`prefers-reduced-motion` 块因没有动效可关而成为死代码 | 界面像截图而不是软件。动效是"有人用过它"的唯一证据 |
| 2 | **无 token 层** | CSS 变量只有 13 个（都在 `.studio-app`），其余颜色全是硬编码；约 **30 个手写十六进制绿色** | 系统不存在，只有一堆一次性的取值 |
| 3 | **色族混用** | 冷灰 `#26292d`/`#303438`/`#3b3e42` 与暖橄榄 `#1c1f22`/`#252a27`/`#3d4a41` 在同一视图内混用 | 冷暖混灰是"逐块调的"痕迹，会让人眼觉得脏 |
| 4 | **无深度** | 只有 2 处 `box-shadow`，都是 `#0004` / `#0002` 纯黑；无纹理、无内高光、无层次 | 纯黑低透明投影是最容易被识别的机器默认值 |
| 5 | **字号没有下限** | 大量 9px / 10px；正文 13px；`--fs` 无系统 | 中文在 9px 下不可读。凑尺寸而非排版 |
| 6 | **字重与字距贫乏** | 只用 400/500/600；全项目 **2 个** `letter-spacing`（`.08em` 与 `-.02em`） | 层级只靠字号，标题没有"被排过"的感觉 |
| 7 | **字体靠系统运气** | 正文衬线栈 `"Noto Serif CJK SC","Source Han Serif SC","SimSun"` — 前两者 Windows 默认不装，实际大概率回退到 **SimSun** | 回退字体是设计失控最常见的形态：你看到的和你设计的不是同一个东西 |
| 8 | **选中态=换颜色** | 章节选中整行染 `#3c4940` | 状态用颜色而不是结构（缩进/标记/字重）表达，是新手做法 |
| 9 | **圆角全统一** | 全项目 3/4/5/6/7/8/9px 随机出现，但没有层级逻辑 | 统一或随机的圆角，都缺少"装配感" |
| 10 | **无按下反馈** | 全项目无 `:active` | 缺触感 |
| 11 | **修饰性但不成系统** | `.studio-project-cover` 的书脊、地图的竖排标签、印章位置 | 方向对，但没有成为一套语言 |
| 12 | **两套实现并存** | `Studio.tsx` / `StudioSidebar.tsx` / `StudioHeader.tsx` / `AgentPanel.tsx` / `KnowledgePage.tsx` 是旧稿，与活动的 `StudioApp.tsx` 并行；两套 Icon 组件（`Icon.tsx` / `StudioIcon.tsx`）并存 | 命名与样式两套并行 → 无法建立单一视觉语言 |

**判断：本项目需要的是"工艺补齐"，不是"重新设计"。** 四栏骨架、暖白纸面、编辑稿的概念都是对的，应该保留。

## 3. 诊断方法：怎么练出这只眼睛

这套方法可以直接复用到任何项目。

### 3.1 五个"减法"测试

1. **灰度测试**：截图转灰度。如果层级仍然清楚，说明你的层次来自明度（好）；如果全糊了，说明你依赖颜色而不是明度（差）。
2. **截图测试**：把界面截成静态图。看起来像"软件的截图"还是"一张设计稿"？动效缺失会让它永远像后者。
3. **缩略图测试**：缩到 25%。视觉重心还在吗？还是只剩一堆等权的灰色块？
4. **一致性测试**：随机挑 3 个按钮，把它们的设计值列出来。取值一样吗？不一样的话，是你决定的还是随手写的？
5. **回退测试**：把字体栈里前 3 个字体全部删掉，界面塌了吗？塌了就说明你在依赖运气。

### 3.2 数数法

把"感觉"变成"数字"，因为数字可以被检查、可以被验收：

```powershell
# 在 paraselene-work 下运行，统计四个 studio 样式表
$css = Get-ChildItem src/features/studio/*.css
# 硬编码颜色数量
(Select-String -Path $css -Pattern '#[0-9a-fA-F]{3,8}\b' -AllMatches).Matches.Count
# transition / animation 数量
(Select-String -Path $css -Pattern 'transition|@keyframes').Count
# 出现过的所有 font-size
Select-String -Path $css -Pattern 'font-size:\s*([\d.]+)px' -AllMatches |
  ForEach-Object { $_.Matches } | ForEach-Object { $_.Groups[1].Value } | Sort-Object {[double]$_} -Unique
```

**经验阈值**（来自下面第 4 节那些成熟系统的一致做法）：

- 硬编码颜色 > 30 个 → 缺 token 层
- `transition` 数 < 交互元素数的 1/3 → 缺动效层
- 最小字号 < 11px（中文） → 缺排版下限
- `letter-spacing` 取值 < 3 种 → 缺字距系统
- 色相跨度 > 60° 的中性色同时出现 → 色族混用

### 3.3 "它像哪个真实产品"测试

拿你的界面问：**它最接近哪个已存在的好产品？** 说不出具体名字，就说明它没有身份。这个项目能说出（Zed 的骨架 + 编辑稿的纸面），所以身份是有的，只是没被做出来。

## 4. 那些"没有 AI 味"的开源系统是怎么做的

完整调查见 [github-design-systems-research.md](./github-design-systems-research.md)（每条带 `[V]` 已验证 / `[C]` 已定位 / `[U]` 未验证 的证据等级标注）。核心观察，都是**不依赖未读数值**的结构性结论：

| 系统 | 可照搬的结构决策 |
|---|---|
| **Radix Colors** | **12 阶色标，每阶有固定语义职责**（1–2 应用底、3–5 组件底、6–8 描边、9–10 强调填充、**11–12 专用于文字**）。因为 11/12 被定义为"文字色"，**对比度成为结构性保证，而不是逐组件碰运气**。 |
| **shadcn/ui** | **单一 `--radius` 根值 + `calc()` 派生** sm/md/lg/xl。这正是 AI 生成的 CSS 缺的"一个旋钮、几何一致"性质 —— AI 输出往往每个组件硬编码一个不同圆角（本项目**10 个不同圆角值**，正是此症状）。 |
| **GitHub Primer** | 阴影**按角色**而非按大小分：`--shadow-resting-*`（静置）/ `--shadow-floating-*`（悬浮）/ `--shadow-inset-*`（内嵌）。 |
| **Tailwind v4** | **每个字号自带配对行高**（`--text-*`），**单一间距乘数**，阴影刻度是**多层且带色调**而非纯黑。 |
| **IBM Carbon** | 4px 最小单位 / 8px 网格，间距与动效都是**第一等 token**，不留给实现者随手决定。 |
| **Geist** | 中性色是 **100–1000 刻度**并按色族分开（约 80 阶），**刻意不用纯 `#000`/`#fff` 作为两端**。 |
| **Ant Design** | 唯一在本次调查中确认为字面值的阴影：`0 1px 2px 0 rgba(0,0,0,0.05), 0 1px 6px -1px rgba(0,0,0,0.03)` —— **两层、5%/3% 低透明、近偏移、带负 spread**。 |

**三条能立刻用上的判据：**

1. **投影形状**：crafted = 多层 + 低透明（5%/3%）+ 近偏移 + 可负 spread；AI 默认 = 单层 + 大范围 + 较高透明。**本项目是 3 处单层纯黑 `#0004`/`#0002`，属于后者。**
2. **对比度要靠结构**：把"文字色"固定在某几阶上，而不是每个组件各挑一个。**本项目反例：全局焦点环 `--studio-accent: #acd4c2` 在纸面 `#f8f6f0` 上只有 1.50:1**（实测计算），远低于非文本对比度 3:1 下限。目前只是靠"`StudioContent.css` 在 `StudioApp.css` 之后被 import"这个**源码顺序巧合**，才由 `StudioApp.css:85` 的 `#607f62`（4.13:1）救回来 —— 一旦调整 import 顺序，纸面焦点环就会失效。
3. **动效的反直觉要点**：最高工艺往往"感觉不到缓动"，重点是**状态反馈的确定性**（每个可点元素都有 hover/active/focus），而不是时长和弹跳。**本项目是另一个极端：全站 1 处 transition、0 处 `:active`、0 处 `cursor`。**

**⚠️ 证据局限**：本次调查环境**无法读取任何网页正文**（`web_fetch` 对所有域名均失败）。因此上表是**结构结论 + 精确落点**，不是数值转录。被刻意标注为 `[U]` 的（Tailwind 真实 `--shadow-*` 字符串、Carbon 毫秒表、CJK 字体 MB 数、Material 的 cubic-bezier 控制点）**需要网络才能补齐，本次没有编造**。有网络后优先打开的 10 个链接见该文件第 6 节。

## 5. 施工方案（分阶段，按"性价比 / 风险"排序）

原则：**只动设计变量与状态层，不动布局结构与业务逻辑。** 每一阶段都可独立验收、可回滚。

### 阶段 0：清理障碍（不改视觉）

- 决定 `Studio.tsx` 旧稿与 `StudioApp.tsx` 的归属：冻结或删除旧稿，统一到一套 Icon 组件。**两套并行时，任何 token 化都会被稀释。**

### 阶段 1：Token 层（不改视觉，只重构）

把 `StudioApp.css` 顶部的 13 个变量扩成一个完整 token 层，并把四个样式表里所有硬编码颜色/字号/间距改为引用。**此阶段像素级零变化**，目的是让后面每一步都变成"改一个值"。

建议 token 组：色（底/面板/抬高/描边/墨/次要/强调/纸面组）、字（族/号/重/行高/字距）、间（4px 刻度）、圆角（4 档）、影（3 档）、动（时长/缓动）。

### 阶段 2：字体与排版（视觉变化最大，风险最低）

- 字体栈换成"拉丁优先 + 中文兜底"，正文换真衬线（见排版专项）。**该项最高优先级的一个具体原因：当前正文衬线栈是 `"Noto Serif CJK SC","Source Han Serif SC","SimSun"`，而前两者 Windows 默认不装 —— 也就是说你现在看到的正文，很可能根本没有用上衬线，而是回退到了宋体或雅黑。**
- 建立字号刻度：正文 14px 起，micro 下限 11px。**当前有 43 处 ≤10px，其中 9px 有 9 处，包含"保存状态"和"字数统计"这两个核心反馈。**
- 中文正文补 `text-indent: 2em`、`text-wrap: pretty`、`line-break: strict`。
- **`text-align` 用左对齐，不要用 `justify`。** 中文的 justification 靠拉伸字间空白实现（而非拉伸词间空格），会导致同段落内字距时紧时松的斑驳感，对长篇阅读是负价值。（此条修正了本手册初稿的建议。）
- 数字统一 `font-variant-numeric: tabular-nums`（字数、章节号、统计）—— 否则字数从 999 涨到 1000 时整块 UI 会左右抖动。
- 字重刻度补 500/600 的明确用途，字号大的标题加负字距。

### 阶段 3：动效层（质变，风险低）

- 全站统一 2–3 个时长与 1 条缓动曲线，禁止逐处自定义。
- 补齐 hover / active / focus / selected 四态，尤其是 `:active` 的 `scale`。
- 浮层（导出菜单、搜索弹窗、toast）加入进场：透明度 + 4px 位移，180ms。
- 面板收放（Agent 栏、侧栏）用 transform 而非 `display`。
- 保留并让 `prefers-reduced-motion` 块重新有意义。

### 阶段 4：深度与质感（需要审美判断）

- 投影改为 3 层带色调，单一光源（正上方）。
- 浮层加 1px 内高光模拟边缘折射。
- 全局 2–3% 噪点覆盖，破掉纯数字的平板感。
- 纸面加极轻的暖色径向渐变，避免死平。

### 阶段 5：状态与语义（"完成度"）

- 选中态从"整行换色"改为"结构标记 + 中性抬高"。
- 补齐 loading（骨架屏，不用转圈）、empty、error 三态。
- disabled 与 pending 视觉区分。
- 圆角建立层级（内层小、容器大）。

### 阶段 6：身份（最后做，但决定上限）

- 把"编辑稿"的纸感做成一贯语言：书脊、印章、竖排标签、页码。这是本项目最有可能形成辨识度的方向。
- 图标系统统一：描边粗细随尺寸补偿（小图标不能沿用大图标的相对描边）。

**验收方式**：每个阶段结束后截同一张图对比，并跑 `pwsh -NoProfile -Command "node node_modules/typescript/bin/tsc --noEmit"` 与生产构建，确保零功能回归。

## 6. 给 AI 下指令时怎么写（可直接复用的方法）

**不要**说："让界面更精致一点"、"去掉 AI 味"、"做得更专业"。这些指令无法执行，模型只能回退到默认值。

**要**把审美翻译成可验证的约束。模板：

```text
约束（必须逐条满足，不得自行发挥）：
- 颜色：只能使用下列 9 个值，不得新增。底 #1a1d20、面板 #202427、抬高 #2a2f33、
  描边 #333a3e、主墨 #e8ebe9、次墨 #9aa3a6、强调 #5f9d7f、纸面 #faf9f6、纸墨 #33383a。
- 字号：只能取 11/13/14/17.5/22/30px 六档，正文不得小于 14px。
- 间距：只能取 4 的整数倍。
- 圆角：控件 6px、卡片 10px、浮层 14px、标签 999px，不得新增。
- 动效：统一 180ms cubic-bezier(.32,.72,0,1)，所有可点元素必须有 hover/active/focus 三态。
- 投影：只用三层带色调阴影，禁用纯黑 rgba(0,0,0,x)。
- 禁止：紫蓝渐变、纯黑背景、Inter 之外的"默认感"字栈（除非指定）、emoji 图标、
  玻璃拟态、居中对称的三栏网格。
- 中文正文：首行缩进 2em、两端对齐、行高 1.9–2.0、标点悬挂。

参考物：把 <某个具体产品的具体界面> 作为唯一参照，说明你借鉴的是它的哪一条规则。
交付前自检：逐条列出上面每一条在你的改动里落在哪个文件哪一行。
```

三条关键经验：

1. **给封闭集合，不给形容词。** "只能这 9 个颜色"比"配色要高级"强 100 倍。
2. **要求自证。** "逐条列出落在哪个文件哪一行"会显著降低模型偷懒回退默认值的概率。
3. **一次一层。** 字体、动效、深度分三次做。一次要求全部，模型会在每一层都取中庸解。

## 7. 本项目的最终判断

- 现有布局与概念**保留**，不需要重做。用户说的"整体布局可以"是对的。
- 改动集中在**样式与状态层**，可以渐进式替换，不存在"推翻重来"的必要。
