## Python 沙箱 spike 数据（ADR-0002）

Pyodide（spikes/pyodide/spike.mjs）：冷加载 2529ms / 热 1325ms；RSS +83MB（31→114MB）；包体积 14MB；虚拟 FS 内 `C:/Windows/win.ini` 不可达（FS-BLOCKED）；**Node 环境下网络可连（NET-ACCESSIBLE）**——证明沙箱边界取决于宿主环境，WebView2 必须禁 Node 集成。

本地子进程（spikes/pyprocess/spike.mjs）：启动+执行 87ms；但默认 **FS-ACCESSIBLE**（可读 `C:\Windows\win.ini`）、**NET-ACCESSIBLE**（可连 example.com:80）——裸 subprocess 不满足 G13，Windows 真隔离需 Job Object + 受限令牌，成本高。

**结论：v1 用 Pyodide（WebView2 纯浏览器上下文），练习窗口按需加载。**

## 排障记录（已知坑，复用价值高）

1. `link.exe` 冲突：Git Bash 的 GNU coreutils `link` 抢占 PATH，MSVC 式报错先查 `where link`。
2. 权限名格式：tauri 2.11 capabilities 用 `core:window:allow-start-dragging`（冒号式）；手动复现 build script 时 DEP_* 环境变量缺失会导致权限列表为空，误导排查方向。
3. `DEP_TAURI_DEV` 缺失 panic：target 目录混用 MSVC/GNU 产物导致，全量 `cargo clean` 解决。
4. windres 预处理依赖 gcc（cc1 又依赖 libmpfr/libisl 等 DLL）：最小集是 gcc+binutils+gcc-libs(15.2.0)+libwinpthread+crt-git+gmp/mpfr/mpc/isl/zstd。
5. crate-type 含 cdylib 时 rustup 自包含 lld 报 `export ordinal too large: 90895`；Windows-only 项目改为 `crate-type = ["rlib"]`。
