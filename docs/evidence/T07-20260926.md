## 架构要点（决策记录）

1. **LLM 调用全在 Rust 侧**（crates/llm-core，纯 Rust 不依赖 Tauri）：reqwest(rustls) + SSE 状态机（移植 mycli，注释引用源行号；done 事件延到流尾以带 usage——两个源语义都保留并有顺序测试）。取消 = drop future（对应 mycli 信号树单向广播语义）。
2. **上下文组装与发送分离**：`assemble_chat(gate, request, model) -> PreparedChat`（预览）→ `send(prepared, key)`（发送）。G16 的"外发前可见"由同一份 PreparedChat 结构保证，防漂移测试固化。
3. **CloudGate trait 注入**：llm-core 不依赖 settings 存储；src-tauri 的 SettingsGate 读 memory-core settings KV，值为 "false" 时组装即拒绝（拒绝早于网络活动）。
4. **Key 红线**：keyring 条目 `dev.paraselene.app / deepseek-api-key`；`has_api_key` 只返布尔；keyring 往返测试用独立 test 账号并做旧值备份恢复（修复了初版会误删真实 Key 的缺陷）。
5. **工具调用累积**：index→条目、首块建条目、后续只拼 arguments；BTreeMap 保序。

## 插曲与修正（诚实记录）

- **测试覆盖真实 Key 的缺陷**：初版 key.rs 单测和 ipc_smoke 集成测试都直接写真实账号（deepseek-api-key）再删除——用户存了真实 Key 后跑测试会把它抹掉。已修复：单测用独立 test 账号；集成测试先备份旧值再恢复。
- **SSE 移植源的发现**：mycli 的 sse-parser.ts 的 feed() 是透传降级骨架，完整规格在模块文档注释与测试文件里——按规格逐状态实现，注释引用源行号。
- **工具调用 name 累积**：采用规格注释版（id/name 只来自首块），未采用 openai-compat.ts:197 的 `name +=`（会对重复 name 产生 "readread"）。
